## Why this decision matters

A prompt is one part of an interface, not an authority boundary. Specify the task, available evidence, uncertainty behavior, and output fields. Treat the response as untrusted data that must be parsed and validated before use. Valid JSON does not establish factual correctness, and a schema cannot prove a cited passage supports a claim.

Keep trusted application instructions separate from retrieved content. An excerpt may contain instructions addressed to a reader; it must remain source data. Record a prompt revision whenever you change intended behavior, then rerun the same evaluation cases. Do not collect hidden reasoning; collect concise decision labels, sources, and observable tool results.

## Vocabulary used in this session

### Output contract

Allowed fields, types, statuses and invariants checked before a response is used.

### Citation integrity

Referenced source IDs must exist in the selected evidence set.

### Factual support

A cited passage must actually establish the answer’s claim.

No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
import json
def validate(raw, known):
    try:
        data = json.loads(raw)
    except (ValueError, TypeError):
        return ['invalid_json']
    if type(data) is not dict or set(data) != {'status','answer','citations'}:
        return ['fields']
    if data['status'] not in ('answer','clarify','abstain') or type(data['answer']) is not str:
        return ['types_or_status']
    cites = data['citations']
    if type(cites) is not list or any(type(x) is not str for x in cites):
        return ['citation_type']
    if len(set(cites)) != len(cites) or any(x not in known for x in cites):
        return ['citation_identity']
    if data['status'] == 'answer' and (not cites or not data['answer'].strip()):
        return ['answer_requires_evidence']
    return []
valid = {'status':'answer','answer':'Unopened items within 14 days.','citations':['returns-v1']}
assert validate(json.dumps(valid), {'returns-v1'}) == []
assert validate('{', {'returns-v1'}) == ['invalid_json']
assert validate(json.dumps(dict(valid, citations=['invented'])), {'returns-v1'}) == ['citation_identity']
unsupported = dict(valid, answer='Opened items are always eligible.')
assert validate(json.dumps(unsupported), {'returns-v1'}) == []
print('structure and identity passed; unsupported claim still requires factual review')
```

## Walk through the mechanism and its limits

Parsing, exact keys, types, membership and answer invariants are separate checks with separate failure reasons. The last assertion deliberately passes an unsupported sentence. This proves the limit of validation: reference existence is not evidence that the passage supports a claim. A reviewer or separately evaluated support check must compare the actual wording and policy conditions.
