## Why this decision matters

Retrieval starts with reliable ingestion. Normalize line endings and encoding without deleting meaningful boundaries, headings, dates, or exclusions. Keep the original document and a normalized representation so you can investigate how an answer was produced. A document ID identifies a source; a revision or content hash identifies its particular contents.

Separate upload acceptance from readiness to search. An accepted file may still fail parsing or indexing. Represent states such as received, parsed, indexed, and failed explicitly. A new policy revision must not quietly coexist with an old active rule unless the question specifies an historical date. Use synthetic plain text for this program; complex PDFs are an optional extension.

## Vocabulary used in this session

### Source revision

A specific version of a document with a stable identity and content hash.

### Ingestion state

An explicit stage such as received, parsed, indexed or failed.

### Active policy

The source revision selected under a documented effective-date rule.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Source revision

A source revision binds identity to exact bytes and an effective date. Preserve raw text and a digest before normalization so a later run can be traced to what was ingested. Reusing a revision ID for different text breaks reproducibility. Hash equality establishes byte identity, not that a policy is authorized or correct.

## Step 2 · Ingestion state

Ingestion has stages: received, parsed, indexed, then eligible for activation. Upload success is not index success. A failed parse should retain its error and leave the current working revision active. Prepare the replacement in parallel rather than deleting the old source before you know the new one is usable.

## Step 3 · Active policy

An active-policy rule must account for effective time as well as readiness. A successfully indexed future policy must not answer a current-date request. Historical queries may need an earlier revision even after the active pointer changes. The small practice adds this gate; it does not solve all temporal query semantics.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
import hashlib
versions, active = {}, {}
def ingest(document, revision, text):
    key = (document, revision)
    fingerprint=hashlib.sha256(text.encode()).hexdigest()
    if key in versions:
        if versions[key]['digest']!=fingerprint:raise ValueError('revision_content_conflict')
        return key
    versions[key] = {'text':text, 'digest':fingerprint, 'indexed':False}
    return key
def activate(key):
    if not versions[key]['indexed']:
        return False
    active[key[0]] = key
    return True
v1 = ingest('returns','v1','Unopened items: 14 days.')
versions[v1]['indexed'] = True
assert activate(v1)
v2 = ingest('returns','v2','Unopened items: 21 days.')
assert not activate(v2) and active['returns'] == v1
versions[v2]['indexed'] = True
assert activate(v2) and versions[v1]['text'].endswith('14 days.')
print('v1 retained; v2 activated only after indexing')
```

## Walk through the mechanism and its limits

The hash identifies exact source bytes; it does not prove correctness or effective date. The active pointer changes only after the new revision is ready. Keeping v1 enables historical references and recovery. This in-memory demonstration shows the lifecycle invariant; production activation must also check evaluation/effective dates and commit its pointer atomically in durable storage.
