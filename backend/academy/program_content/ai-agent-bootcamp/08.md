## Why this decision matters

Chunking decides what unit of evidence can be retrieved. Fixed-length cuts are easy but can separate a condition from its exception. Begin with heading-based sections and include a small parent context where needed. Evaluate chunking through retrieval outcomes rather than choosing a size because a tutorial used it.

A lexical baseline helps you see the problem before adding embeddings. Rank source sections by normalized term overlap, retain deterministic tie-breaking, and label the method honestly. A lexical system will miss paraphrases and may overvalue shared words. That limitation becomes a concrete reason to compare a semantic method later.

## Vocabulary used in this session

### Chunk

A retrievable section that retains enough context to interpret its rule.

### Lexical retrieval

Ranking using word or term overlap rather than semantic meaning.

### Recall at k

The fraction of relevant gold passage IDs retrieved among the first k results; no-source cases need separate scoring.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Chunk

A chunk is a retrievable unit of meaning, not just an arbitrary character slice. Keep a rule with its exception and include document/revision/passage identity. If “opened items excluded” is split away, retrieval may return a plausible but misleading rule. Compare chunking on fixed labeled questions rather than admiring shorter sections.

## Step 2 · Lexical retrieval

Lexical retrieval counts shared terms and breaks ties deterministically by passage ID. It does not recognize synonyms unless you add a documented normalization rule. The fixture’s delivery query misses shipping, even though a human sees the relation. Preserve that failure in the report before trying a more expensive retriever.

## Step 3 · Recall at k

Passage recall at k is the number of relevant gold IDs retrieved in the first k divided by the number of relevant gold IDs. With two required passages and one retrieved, recall is one half. Case hit rate asks only whether any relevant passage appeared. Empty-gold questions need a separate no-source measure, not division by zero.

## Worked implementation: Chunking and a lexical retrieval baseline

## Walk through the data and decision

1. retrieve tokenizes query and passages with the same lower-case word expression.

2. delivery produces no shared terms with shipping, so it returns an empty list.

3. The baseline one-gold example has recall 0 at one and 1 at two.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
import re
def retrieve(query, passages, k):
    words = set(re.findall(r'[a-z]+', query.lower()))
    ranked = [(len(words & set(re.findall(r'[a-z]+', p['text'].lower()))), p) for p in passages]
    ranked.sort(key=lambda pair: (-pair[0], pair[1]['id']))
    return [p['id'] for score,p in ranked if score > 0][:k]
passages = [{'id':'returns-2','text':'Return an unopened item within 14 days. Opened items excluded.'},
            {'id':'shipping-1','text':'Shipping takes five working days.'}]
assert retrieve('return unopened item', passages, 1) == ['returns-2']
assert retrieve('astronomy', passages, 3) == []
assert retrieve('delivery', passages, 3) == []
ranked, gold = ['shipping-1','returns-2'], {'returns-2'}
recall_at_1 = len(set(ranked[:1]) & gold) / len(gold)
recall_at_2 = len(set(ranked[:2]) & gold) / len(gold)
assert (recall_at_1, recall_at_2) == (0, 1)
print('recall@1=0; recall@2=1; lexical delivery/shipping mismatch remains')
```

## Walk through the mechanism and its limits

Set overlap is a deliberately simple baseline. Filtering zero scores prevents unrelated passages being treated as evidence. Sorting by ID resolves ties reproducibly. The second experiment uses fixed ranked IDs to distinguish ranking metrics from generation quality: finding a passage within k does not prove the answer uses it. The baseline misses synonyms and ignores negation.
