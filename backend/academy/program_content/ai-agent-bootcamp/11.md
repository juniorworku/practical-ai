## Why this decision matters

An agent loop observes a state, chooses an allowed next action, invokes a tool, and incorporates the result. Without explicit stopping conditions, it can repeat the same ineffective action indefinitely. Model state as application data rather than an accumulating string of conversation.

Use states such as needs_context, drafting, needs_review, done, and failed. Record the tool result and transition that occurred, not an imagined successful action. Enforce maximum steps, overall time, and budget outside the model. Compare the loop with a fixed retrieve-then-draft workflow; agency must justify its added complexity through measurable gains.

## Vocabulary used in this session

### Agent state

Structured application data recording observed results and the current stage.

### Transition

An explicitly permitted movement between states.

### Step limit

An application-enforced maximum number of iterations independent of model instructions.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Agent state

Agent state records observations and stage, not just conversational prose. A trace lets you distinguish a successful answer from a partial retrieval followed by failure. Persist only the state you need, with a run identity and source revisions. The baseline is an offline list of decisions, so it tests control flow rather than a model’s planning quality.

## Step 2 · Transition

A transition is a permitted movement based on current state and observed result. Reject an unknown action, and record tool exceptions as failed observations. Merely appending a requested action does not prove its tool completed. Validate both name and outcome before moving to a state that assumes evidence exists.

## Step 3 · Step limit

A step limit bounds iterations even when the model asks to continue. It does not bound a single slow tool, so add an overall deadline as a separate constraint. Count elapsed work and waits, terminate visibly on exhaustion, and compare this loop with a fixed workflow on identical tasks before claiming added autonomy helps.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
def run(decisions, max_steps=3):
    trace = [];state='start'
    allowed={'start':{'retrieve','abstain'},'evidence':{'retrieve','answer','abstain'}}
    for action in decisions:
        if len(trace) >= max_steps:
            return {'status':'step_limit','trace':trace}
        if action not in allowed[state]:
            return {'status':'failed','trace':trace + ['rejected:'+action]}
        trace.append(action)
        if action=='retrieve':state='evidence'
        if action in {'answer','abstain'}:
            return {'status':action,'trace':trace}
    return {'status':'needs_context','trace':trace}
assert run(['retrieve']*3 + ['answer'])['status'] == 'step_limit'
assert run(['retrieve','answer'])['trace'] == ['retrieve','answer']
assert run(['retrieve','delete'])['status'] == 'failed'
assert run([])['status'] == 'needs_context'
assert run(['answer'])['status']=='failed'
print('terminal states: answer, abstain, step_limit, failed; no fabricated success')
```

## Walk through the mechanism and its limits

The decision list replaces a model so control flow can be inspected deterministically. The runtime checks the step budget before executing another proposal. Only an allowed terminal action ends successfully. This example bounds steps but not time, tokens, or tool exceptions; those must be added explicitly rather than inferred from a finite loop.
