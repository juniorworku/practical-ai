## Why this decision matters

A retrieved document can contain instructions that conflict with the user’s task. Treat its text as data even when it claims to be a system message or an administrator. Prompt wording is only one defense; tool permissions, data access, action approval, and output validation must remain enforced by application code.

Threat-model the assets and trust boundaries: private documents, provider credentials, source retrieval, model output, tool dispatch, and external actions. A successful attack is defined by an unauthorized disclosure or effect, not merely the model repeating suspicious words. Use synthetic canary values and local fake tools when testing.

## Vocabulary used in this session

### Prompt injection

Untrusted content attempts to redirect the system’s behavior or authority.

### Trust boundary

A separation where data from one source cannot automatically grant privileges in another.

### Canary fixture

A synthetic recognizable value used to test unauthorized disclosure without real secrets.

## Worked implementation: Prompt injection and untrusted documents

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
records = {'p1':{'owner':'acme','text':'Return unopened within 14 days.'},
           'private':{'owner':'other','text':'CANARY-OTHER-SECRET'}}
def lookup(actor, identifier):
    record = records.get(identifier)
    return record['text'] if record and record['owner']==actor else 'inaccessible'
def dispatch(actor, proposed):
    name, identifier = proposed
    if name != 'lookup':
        return 'tool_denied'
    return lookup(actor,identifier)
# These are adversarial model proposals, not commands executed by this file.
results = [dispatch('acme',p) for p in [('send_files','all'),('lookup','private'),('lookup','p1')]]
assert results == ['tool_denied','inaccessible','Return unopened within 14 days.']
assert 'CANARY-OTHER-SECRET' not in str(results)
print('forbidden operation and allowed-tool cross-owner attack both denied')
```

## Walk through the mechanism and its limits

Testing only forbidden tool names misses attacks that abuse an allowed lookup with an unauthorized ID. The ownership check remains inside the tool regardless of what the retrieved document says. Synthetic proposals test enforcement, not whether a particular model resists instructions; those are distinct evaluations. This narrow example cannot establish that every output channel or logging path is safe.

## Break it deliberately

A malicious document uses a real allowlisted tool name with another user’s record ID. Test the ownership check inside that tool independently of the prompt.

## Acceptance checks

- Untrusted text cannot establish identity or authorize a tool.
- Canary secrets are not present in outputs or logs.
- The report distinguishes prompt behavior from enforced permissions.
