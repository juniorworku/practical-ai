## Why this decision matters

Graphs, durable workflows, and multi-agent systems solve different coordination problems. A graph makes state transitions explicit. Durability preserves progress across interruption. Multiple agents introduce communication and responsibility boundaries. None automatically improves answer quality or removes the need for authorization.

Use your observed capstone failures to choose an extension. A fixed pipeline may already be sufficient. If a job must pause for human review and resume after restart, durable state matters more than adding a second model persona. Write the decision in terms of correctness, recovery, latency, and maintenance rather than fashionable tool names.

## Vocabulary used in this session

### Explicit graph

A representation of permitted workflow states and transitions.

### Durability

Progress survives interruption because required state is persisted outside the process.

### Architecture baseline

The simpler design against which added complexity is evaluated.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Explicit graph

An explicit graph names states and permitted edges such as draft → waiting_review → ready. It helps when the workflow has branches, pauses or retries that need inspection. A graph framework does not remove the need for owner checks, versioning and stop conditions. Compare its operational cost with a fixed function chain before adopting it.

## Step 2 · Durability

Durability means state survives the relevant process boundary. An in-memory variable cannot resume after a restart. Persist state and version, reopen storage and apply a conditional transition so an old review does not replay work. The SQLite fixture demonstrates a single-record transition, not durable remote effects or multi-region coordination.

## Step 3 · Architecture baseline

An architecture baseline keeps the task and dataset fixed while comparing implementations. Count added coordination calls, latency, failure modes and review quality. Choose a framework because it resolves an observed requirement such as a durable pause, not because a multi-agent diagram looks sophisticated. Keep one simpler implementation to reveal whether complexity adds value.

## Worked implementation: Choose orchestration complexity deliberately

## Walk through the data and decision

1. The job is committed as waiting_review version 2 before closing the connection.

2. resume changes only the matching waiting version to ready version 3.

3. A duplicate version-2 resume updates zero rows.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
import sqlite3
from tempfile import TemporaryDirectory
from pathlib import Path
with TemporaryDirectory() as folder:
    path = Path(folder)/'jobs.sqlite'
    db = sqlite3.connect(path)
    db.execute('CREATE TABLE jobs(id TEXT PRIMARY KEY,state TEXT,version INT)')
    db.execute('INSERT INTO jobs VALUES(?,?,?)',('j1','waiting_review',2))
    db.commit(); db.close()
    db = sqlite3.connect(path)
    def resume(expected):
        with db:
            return db.execute("UPDATE jobs SET state='ready',version=version+1 WHERE id='j1' AND state='waiting_review' AND version=?",(expected,)).rowcount
    assert resume(2)==1 and resume(2)==0
    assert db.execute('SELECT state,version FROM jobs').fetchone()==('ready',3)
    db.close()
print('resume survives reopen; duplicate version-2 transition has zero effect')
```

## Expected observation

```text

```

## Walk through the mechanism and its limits

The persisted waiting state survives closing the connection. A conditional transition consumes a particular version once, so replaying the same review cannot advance it twice. This solves one requirement—durable review resumption—without introducing multiple agents. It does not make a subsequent external send atomic; that still requires the effect ledger from the approval lesson.

## Apply the three engineering pillars

## Software-first practice

Build interfaces, asynchronous services, API adapters and recoverable data flows before studying algorithm derivations. Use mathematics to explain a measured engineering decision.

## Production evidence

A notebook or chat demo is an early prototype. Completion requires operational evidence: deployment/readiness, bounded work, rate limits, error recovery and persisted state. The 10% framing is a teaching heuristic, not a measured universal percentage.

## Apply the three pillars to A multi-user AI service deployed from containers

### Latency vs. Cost vs. Quality

Load-test offered vs. completed work, p95 and cost per accepted result at stated concurrency. Autoscaling settings are hypotheses until observed against downstream/GPU limits.

### Deterministic Evaluation

Test readiness against the actual database, restart/readback, isolated restore, denied owner access, overload rejection and a dependency outage on the deployed revision.

### Context Management

Budget resident model memory/KV cache and per-request context separately. Keep tenant/revision-aware application caches; never assume a process-local cache is shared across replicas.

## Failure and deployment work

Separate request concurrency, worker capacity and model/GPU capacity. Add admission control, shared quotas, bounded queues, maximum instances and a documented fallback/stop budget.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
