## Why this decision matters

A finished learning project is understandable and reproducible without the author narrating every step. Package the problem brief, architecture, setup, evaluation report, threat model, operational runbook, and known limitations. Use fictional or permissioned examples in a portfolio. A model integration is optional; if present, document provider selection, consent, measured usage, and failure behavior.

Prioritize the next release from observed failures and user needs. Separate defects that undermine the current promise from optional extensions such as semantic retrieval, durable jobs, or MCP interoperability. Keep a short decision log so future changes do not undo deliberate constraints. The final artifact is a maintainable system and its evidence, not a claim of mastery.

## Vocabulary used in this session

### Handover package

Setup, scope, architecture, evaluation, operations and limitations usable without the author present.

### Scoped claim

A statement of capability limited to the conditions actually tested.

### Evidence-driven backlog

Future work prioritized from observed defects and user needs with acceptance checks.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Handover package

A handover package contains executable setup, fixtures, declared dependencies, configuration names, operating instructions and evidence. A hash manifest identifies exact bytes but does not prove those files are sufficient. Ask a fresh operator to follow only the instructions, recording every intervention rather than quietly supplying missing assumptions.

## Step 2 · Scoped claim

A scoped claim says precisely what was tested: offline prototype, source revision, workload and remaining limitations. Detecting a changed fixture does not establish answer quality or production readiness. Link each user-facing promise to its observation and avoid converting synthetic data into a client success story.

## Step 3 · Evidence-driven backlog

An evidence-driven backlog starts with an observed gap and a falsifiable acceptance check. “Improve AI” cannot be verified; “retain input after API timeout and show failure on reload” can. Give the item a reason, owner and prerequisite. Prioritize missing release evidence and user harm before speculative integrations.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import hashlib, json
with TemporaryDirectory() as folder:
    root=Path(folder)
    files={'README.txt':'Run python3 demo.py. Fake provider; no live calls.',
           'demo.py':'print("read-only offline demo")\n','policies.json':'[{"id":"returns-v1"}]'}
    for name,text in files.items(): (root/name).write_text(text,encoding='utf-8')
    manifest={name:hashlib.sha256((root/name).read_bytes()).hexdigest() for name in files}
    (root/'manifest.json').write_text(json.dumps(manifest),encoding='utf-8')
    assert all((root/name).is_file() for name in manifest)
    (root/'policies.json').write_text('[]',encoding='utf-8')
    changed=[name for name,digest in manifest.items() if hashlib.sha256((root/name).read_bytes()).hexdigest()!=digest]
    assert changed==['policies.json']
print('manifest detects changed fixture; hashes identify files, not teaching quality')
```

## Walk through the mechanism and its limits

The manifest binds a release to exact setup and fixture bytes, helping a recipient detect drift. It cannot show the instructions are understandable or complete; that requires a fresh setup performed by another person. A hash also does not establish trustworthiness. Keep the release scope, failure evidence, access-removal steps and known gaps next to this manifest.

## Apply the three engineering pillars

## Software-first practice

Build interfaces, asynchronous services, API adapters and recoverable data flows before studying algorithm derivations. Use mathematics to explain a measured engineering decision.

## Production evidence

A notebook or chat demo is an early prototype. Graduation builds toward operational evidence: deployment/readiness, bounded work, rate limits, error recovery and persisted state. Early checkpoints assess only boundaries already taught; future deployment controls are planned rather than claimed complete. The 10% framing is a teaching heuristic, not a measured universal percentage.

## Apply the three pillars to A multi-user AI service deployed from containers

### Latency vs. Cost vs. Quality

Load-test offered vs. completed work, p95 and cost per accepted result at stated concurrency. Autoscaling settings are hypotheses until observed against downstream/GPU limits.

### Deterministic Evaluation

Test readiness against the actual database, restart/readback, isolated restore, denied owner access, overload rejection and a dependency outage on the deployed revision.

### Context Management

Budget resident model memory/KV cache and per-request context separately. Keep tenant/revision-aware application caches; never assume a process-local cache is shared across replicas.

## Failure and deployment work

Separate request concurrency, worker capacity and model/GPU capacity. Add admission control, shared quotas, bounded queues, maximum instances and a documented fallback/stop budget.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
