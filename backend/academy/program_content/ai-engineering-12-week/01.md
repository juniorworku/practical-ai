## Module 1 · Modern AI Stack & Foundational APIs · system design

Start with an application boundary: an authenticated user asks a question, an adapter sends a bounded request, a stream returns draft events and the application validates/persists the result. Choose capabilities before vendor branding: text, audio input/output, tool calling, context size, residency, quotas and measured latency all affect the interface. An SDK hides transport details but cannot choose your retry policy, trust boundary or quality standard.

Stateless requests carry their selected history each time. Stateful sessions retain provider-side state but still need tenant ownership, expiry, consent and a recovery path. Input token counts are a preflight tool; output/reasoning/tool/cached usage belongs in the completed run record when the provider supplies it. A character or word estimate can help reject obviously oversized work, but it is not measured billing.

Concurrency is a capacity decision. Bounded queues and semaphores prevent a burst of users from becoming unlimited simultaneous provider calls. Cancellation must stop children and release resources when a browser leaves. Set both per-operation timeout and overall deadline; backoff and queue wait consume that deadline. Do not replay an external write merely because a network response was lost.

In voice, separate capture rate, wire encoding, provider input format and playback format. Raw PCM16 is not WebM/Opus. Measure microphone capture → gateway enqueue → provider first audio → audible playback, with a defined start event such as end of speech. A low first-token time can coexist with an unusable playback backlog. Interruptions must clear scheduled sound as well as server generation. Reconnect state is a lifecycle problem rather than permission to replay arbitrary frames.

The supplied gateway includes a visible offline echo mode for protocol testing and an opt-in Gemini adapter. Echo establishes transport/cancellation behavior only; live task correctness, speech intelligibility, provider billing and network latency remain unmeasured until you run an authorized evaluation. Keep server credentials out of browser bundles, require session authorization, restrict origins and impose per-session byte/time/concurrency limits. Record installed SDK and model versions; availability changes, so the model is an explicit configuration value.

## Vocabulary used in this session

### Capability contract

Required input/output modalities, tools, context, residency and failure semantics.

### Provider adapter

Application-owned interface insulating callers from SDK-specific responses.

### Measured usage

Provider-reported token/work counts, distinct from a fixture or estimate.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Capability contract

Start by listing what the caller needs before selecting a model: text input, audio output, tool calls and a maximum context are separate capabilities. A text-only model cannot satisfy an audio-output requirement by changing its prompt. Check the requested capability against explicit adapter metadata before a network call; a rejected request should consume no provider work.

## Step 2 · Provider adapter

A provider adapter translates provider-specific fields into a stable application result. Here Result is a dataclass: its annotated fields define an explicit record, and frozen=True prevents accidental field reassignment after construction. An adapter is useful because the HTTP route can read result.status and result.text without knowing whether the provider called its field content or message.

## Step 3 · Measured usage

Usage has both a quantity and an origin. The supplied 12 input and 5 output counts are synthetic fixture counts, so the record says usage_kind=fixture. Real API usage may be missing or include other categories; do not replace unavailable usage with zero and label it measured. A returned draft also remains distinct from a reviewed, persisted final answer.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class Result:
    status: str
    text: str
    input_tokens: int
    output_tokens: int
    usage_kind: str

def adapter(question):
    if not question.strip(): raise ValueError('question required')
    return Result('draft','Synthetic supported draft',12,5,'fixture')
result=adapter('What is the returns policy?')
assert result.status=='draft' and result.usage_kind=='fixture'
assert result.input_tokens+result.output_tokens==17
print(result)
```

## Apply the three pillars to A provider adapter shared by simultaneous learners

### Latency vs. Cost vs. Quality

Measure time to first output and total completion separately. Compare retry cost and accepted-output rate under a fixed overall deadline.

### Deterministic Evaluation

Fake 429, 503, permission failure, malformed JSON, cancellation and a partial stream. Assert bounded retry and no false saved/success status.

### Context Management

Track actual input/output usage when supplied; include retry usage. Key caches by owner, model, prompt and source revisions; never cache partial streams as complete answers.

## Failure and deployment work

Honor Retry-After within the total budget, stop sibling tasks on disconnect, and separate safe draft retries from uncertain external writes.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
