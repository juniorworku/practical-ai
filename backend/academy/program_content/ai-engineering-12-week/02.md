## Stateless requests, sessions and token accounting · concepts and decision

## Before you begin

Session 1: distinguish application records from provider responses. A SHA-256 digest is an identity fingerprint here, not encryption. Use Python3.12 with assertions enabled. All core practice runs offline with the standard library; provider accounts are only for separately labeled integration work.

## The case

A customer changes from returns-v1 to v2 while a previous answer remains cached.

## Reason through the decision

Invalidate the stale scoped result and rebuild the context under v2; a shared topic string is not a safe cache key.

A stateless completion needs the relevant turns supplied again; a server-side session ID references managed state and still needs ownership and lifecycle rules. The cache fingerprint includes tenant, model, prompt, source revision and actual turns. Omitting one can return another user’s content or a stale answer. The 560-unit allowance is a fixture arithmetic check; a real tokenizer or provider count must replace it before enforcing a model-specific limit.

## Vocabulary used in this session

### Stateless request

A call whose relevant context must be supplied explicitly.

### Session lifecycle

Ownership, expiry and recovery rules around retained conversation state.

### Cache fingerprint

Identity incorporating tenant, model, prompt, source revision and context.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Stateless request

A stateless request does not remember earlier messages merely because they came from the same browser. The application selects and resends relevant turns. A stateful session instead references retained conversation state, but the application must still bind the session to an owner and enforce expiry. These are storage/lifecycle choices; neither guarantees an unlimited context window.

## Step 2 · Session lifecycle

Give retained sessions an owner and an expiry checked on every lookup. For example, a session for acme expiring at time 100 must reject other at time 99 and acme at time 100. Do not use an unguessable-looking session ID as your only permission check. Expired memory can be rebuilt from authorized durable records rather than silently reused.

## Step 3 · Cache fingerprint

The cache key serializes owner, model, prompt/source versions and actual turns before hashing. Changing an input should change the key. A permission revision and expiration are separate validity conditions: an identical hash does not make revoked or expired content usable. The context allowance is window minus instructions, tool schemas, metadata and output reserve; exceeding it should be visible before provider work.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
import hashlib,json
def context_key(owner, model, prompt_version, source_version, turns):
    payload=[owner,model,prompt_version,source_version,turns]
    return hashlib.sha256(json.dumps(payload,sort_keys=True).encode()).hexdigest()
turns=[{'role':'user','text':'Returns?'},{'role':'assistant','text':'Unopened within 14 days.'}]
k=context_key('acme','fixture','p1','s1',turns)
assert k!=context_key('other','fixture','p1','s1',turns)
assert k!=context_key('acme','fixture','p1','s2',turns)
window,fixed,output_reserve=1000,240,200
available=window-fixed-output_reserve
assert available==560
print({'retrieval_allowance':available,'cache_scope_tests':'passed','token_kind':'supplied fixture'})
```
