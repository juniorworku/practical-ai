## Reason through the decision

Cancel scheduled audio nodes, clear queued frames and resume only under documented provider/application semantics.

Receiving an interruption event is insufficient if queued old audio continues playing. Clear the playback queue and stop already scheduled audio nodes; then move to the new turn. The acknowledgement example isolates duplicate sequence handling, not proof that a provider supports replaying arbitrary audio. ## Vocabulary used in this session

### Barge-in

A new user turn interrupts generated audio and queued playback.

### Replay boundary

Which acknowledged events may safely be repeated after reconnect.

### Session secret

A resumption credential scoped to the authenticated session owner.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Barge-in

Barge-in means a new user turn interrupts the old reply. Generation cancellation, server queue removal and browser scheduled-node cancellation are three separate operations. Clearing a Python deque demonstrates only the queue part; the voice appendix also stops scheduled audio nodes. Tagging output with a turn/session identity helps reject late old output.

## Step 2 · Replay boundary

A replay boundary distinguishes acknowledged work from uncertain work. In the fixture, last_ack=7 means sequences 6 and 7 must not be replayed as new. Sequences 8 and 9 are merely unacknowledged; whether audio may actually be replayed depends on the provider protocol. Acknowledgement of transport bytes is also different from approval of an external write.

## Step 3 · Session secret

A session resumption handle can expose retained conversation and therefore acts like a secret. Bind lookup to the authenticated owner and expiry. On reconnect, an old socket can still deliver a late callback: compare the callback connection/generation with the active one before modifying playback or UI. A new connection must not be closed by the old connection’s cleanup.

## Walk through the data and state

1. interrupt clears both old-turn frames and records new-turn.

2. Filtering with seq > last_ack removes already acknowledged sequences 6 and 7.

3. The remaining [8,9] are candidates for protocol-specific recovery, not blanket replay permission.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
from collections import deque
playback=deque([('old-turn',b'frame-a'),('old-turn',b'frame-b')])
state={'turn':'old-turn','interrupted':False,'last_ack':7}
def interrupt(new_turn):
    playback.clear();state.update(turn=new_turn,interrupted=True)
interrupt('new-turn')
assert not playback and state['turn']=='new-turn'
replayed=[6,7,8,9]
accepted=[seq for seq in replayed if seq>state['last_ack']]
assert accepted==[8,9]
print({'queued_old_audio':len(playback),'resume_sequences':accepted})
```
