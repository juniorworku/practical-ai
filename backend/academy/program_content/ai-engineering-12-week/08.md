## The case

## Reason through the decision

Preserve the exception or abstain; compare alternate boundaries rather than maximizing chunk count.

The example preserves a rule and its exception as one section rather than optimizing for equal-sized fragments. Word units are explicitly an estimate, not provider tokens. ## Vocabulary used in this session

### Meaning boundary

A section retaining the conditions needed to interpret a rule.

### Token budget

Allowance for text, metadata, tool schemas and output reserve.

### Chunking evaluation

Comparing boundary policies on fixed relevant-evidence labels.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Meaning boundary

A meaning boundary keeps a claim with the conditions needed to interpret it. “Returns accepted” alone is incomplete if the next sentence excludes opened items. Heading/section boundaries can preserve that relationship; fixed windows are repeatable but may split it. Semantic splitting adds another selection mechanism that must be evaluated rather than assumed superior.

## Step 2 · Token budget

Before selecting chunks, reserve context for instructions, tool schemas, metadata and the answer. Use the target model tokenizer for an actual token limit; a word or character count is only a declared teaching estimate. If one complete rule exceeds the budget, reject it for a reviewed split rather than silently clipping away its exception.

## Step 3 · Chunking evaluation

Compare chunking policies using the same labeled queries and source revision. Record which required evidence appears in the selected context, how much context is spent and whether the final claim is supported. Offsets and locators make a failed boundary inspectable. More chunks or more overlap are costs, not quality metrics by themselves.

```python
sections=[{'id':'rule','text':'Unopened items may be returned within 14 days. Opened items excluded.'},
          {'id':'shipping','text':'Shipping takes five working days.'}]
def chunks(rows,budget):
    result=[]
    for row in rows:
        estimate=len(row['text'].split())
        if estimate>budget: raise ValueError('section needs reviewed split')
        result.append({**row,'estimated_word_units':estimate})
    return result
result=chunks(sections,20)
assert 'Opened items excluded.' in result[0]['text']
try: chunks(sections,3)
except ValueError: print('oversized rule refused; exception stays attached')
else: raise AssertionError('should refuse unsafe split')
```

## Carry rule-and-exception units into the actual retriever

## Before this studio

## Step 1 · Choose a boundary that has an explicit meaning

This corpus treats a blank-line-separated paragraph as one reviewed evidence unit. Splitting every 350 characters can leave a refund rule in one chunk and its exclusion in the next. The query may match only the rule, silently dropping the exclusion. Paragraphs are not universally semantic: the source author or ingestion review must ensure dependent conditions stay together. The example deliberately makes its exception appear beyond the old 350-character cut.

## Step 2 · Rank without losing provenance

Each candidate retains document ID, paragraph position and immutable revision alongside its text. A regex produces lowercase word sets; overlap supplies a transparent lexical score. Stable ID tie-breaking makes repeated fixture runs reproducible. This is not an embedding model or an applicability classifier. Owner filtering must happen before private text reaches this function; adding a scope check after answer construction is too late.

## Step 3 · Refuse a split you have not taught the system to make safely

The 700-character allowance is an explicit evidence budget, not a token limit. A relevant paragraph larger than the allowance raises a reviewed-split error. The final service translates that into needs_correction with no answer or citations. It conservatively refuses even if another smaller passage fits, because silently dropping a relevant exception could mislead. Review the unit or change a measured model-specific budget; do not slice its first 700 characters to make the check pass.

## Step 4 · Keep context selection distinct from answer quality

Whole units are admitted until the character allowance is exhausted. The return value includes selected IDs/text/revisions and actual selected character count. This protects the chosen boundary but cannot prove the selected policy applies to the user. The final extractive fixture labels its model and leaves token usage unknown. Its candidate cache key serializes query, pipeline, route and evidence revisions canonically; no cache is implemented and cache_hit remains false.

## Complete worked example

Save this entire block as example.py in a fresh directory. Run `python3.12 -I example.py` with assertions enabled. All imports are included; no account, provider call or other course is required.

```python
import re
def select_context(text,documents,budget=700):
 """Owner filtering is the caller's responsibility, before passing documents."""
 terms=set(re.findall(r'[a-z]+',text.lower()))
 ranked=[]
 for document in documents:
  # A blank-line-delimited evidence unit must retain its rule and exceptions.
  # Oversized relevant units require a reviewed split, never silent truncation.
  for position,unit in enumerate(document['text'].split('\n\n')):
   unit=unit.strip()
   score=len(terms & set(re.findall(r'[a-z]+',unit.lower())))
   if score:ranked.append((score,document['id']+':'+str(position),unit,document['revision']))
 ranked.sort(key=lambda row:(-row[0],row[1]));selected=[];used=0
 if any(len(row[2])>budget for row in ranked):
  raise ValueError('relevant evidence unit needs a reviewed split')
 for score,id,chunk,revision in ranked:
  if used+len(chunk)<=budget:selected.append((id,chunk,revision));used+=len(chunk)
 return selected,used

text='Refunds within 14 days. '+'Policy detail. '*23+'Opened items are excluded.'
document={'id':'one:policy','revision':'r1','text':text}
selected,used=select_context('refunds',[document])
assert len(text)>350 and selected[0][1].endswith('Opened items are excluded.')
assert used==len(text)
print('rule and exception preserved together; budget counts complete evidence units')
```
