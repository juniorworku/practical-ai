## pgvector search, metadata filters and ANN recall · concepts and decision

## Before you begin

## The case

Another tenant has the closest vector; HNSW filtering leaves fewer than k eligible matches.

## Reason through the decision

Enforce owner/revision scope and measure filtered recall before increasing candidate depth or changing indexing.

Similarity scores do not authorize retrieval. SQL must include tenant and active revision, with a server-established identity. Exact filtered search is a useful small-data baseline before HNSW. Approximate-index filtering can reduce returned matches; observe recall and execution plans rather than assuming LIMIT k always yields k relevant allowed rows. Tenant isolation must hold even when the closest vector belongs to someone else.

## Vocabulary used in this session

### Tenant filter

A server-enforced scope predicate independent of similarity.

### Exact baseline

Exhaustive nearest-neighbor retrieval used to assess ANN loss.

### ANN recall

Measured relevant-result retention under a chosen approximate index.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Tenant filter

Tenant filtering establishes the authorized search universe. Derive owner from server authentication, select the active source revision, then search within that scope. Similarity can only rank eligible records; a closer private vector cannot override permission. An empty result for an unknown owner is expected, not a reason to broaden scope.

## Step 2 · Exact baseline

Exact search considers all eligible vectors and gives a comparison baseline. Approximate nearest-neighbor search such as HNSW avoids some comparisons for speed, which can miss neighbors. Compare latency and retained relevant records under identical authorized filters. The three-row SQL fixture teaches scope and ordering, not an index-performance benchmark.

## Step 3 · ANN recall

ANN retrieval may find global candidates and apply filters in a way that yields fewer than k eligible results. Do not backfill with another tenant. Distinguish “no eligible evidence,” “relevant evidence missed” and “fewer than requested results.” Recall must be measured against labeled authorized evidence and, when evaluating approximation, the exact eligible baseline.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
rows=[{'id':'a1','owner':'acme','revision':'v1','score':.8},
      {'id':'b1','owner':'other','revision':'v1','score':.99},
      {'id':'a2','owner':'acme','revision':'v2','score':.7}]
def scoped_search(owner,revision):
    eligible=[r for r in rows if r['owner']==owner and r['revision']==revision]
    return sorted(eligible,key=lambda r:(-r['score'],r['id']))
assert [r['id'] for r in scoped_search('acme','v1')]==['a1']
assert scoped_search('unknown','v1')==[]
print('tenant and active-revision filter applied before output')
```
