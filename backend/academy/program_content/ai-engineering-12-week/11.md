## The case

Lexical search finds a product code while dense search finds a paraphrased exception.

## Reason through the decision

Fuse scoped candidate lists, deduplicate IDs and compare recall/MRR against each baseline.

Lexical and vector scores have different scales; adding raw values makes an undocumented calibration assumption. Reciprocal-rank fusion combines rank positions without claiming those scores are comparable probabilities. Deduplication prevents repeated IDs in one list from receiving extra votes. Fusion cannot recover a passage absent from both candidate sets, and two weak retrievers do not automatically improve quality.

## Vocabulary used in this session

### Lexical retrieval

Matching terms useful for exact names, identifiers and vocabulary.

### Dense retrieval

Embedding-space similarity useful for semantic candidate selection.

### Rank fusion

Combining rank positions without assuming raw scores share a scale.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Lexical retrieval

Lexical matching is valuable for exact product codes, names and rare terms. Dense retrieval can find paraphrases that share meaning without words. Neither method authorizes a record or guarantees relevant evidence. Keep both lists in the same owner/revision scope before combining them.

## Step 2 · Dense retrieval

Dense retrieval returns similarity-ranked IDs from an embedding space, not calibrated truth probabilities. Lexical and dense score ranges may differ, so a raw sum can let one scale dominate. Preserve each original ranking for comparison; otherwise a claimed hybrid improvement cannot be traced to either source.

## Step 3 · Rank fusion

RRF gives each item a contribution 1/(k+rank) from each list, with rank starting at one. In the fixture b is second lexically and first densely, so it gains two strong contributions. Deduplicate within each list before counting contributions; repeated IDs are not independent votes. MRR then scores the position of the first relevant item for each query.

## Walk through the data and state

1. RRF ignores duplicate IDs inside an individual list via dict.fromkeys.

2. b outranks a because its summed reciprocal-rank contribution is larger.

3. The combined list has four unique IDs; relevant labels are still needed to assess quality.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
def rrf(rankings,k=60):
    scores={}
    for ranking in rankings:
        for rank,identifier in enumerate(dict.fromkeys(ranking),1):
            scores[identifier]=scores.get(identifier,0)+1/(k+rank)
    return sorted(scores,key=lambda identifier:(-scores[identifier],identifier))
lexical=['a','b','c'];dense=['b','d','a']
combined=rrf([lexical,dense])
assert combined[:2]==['b','a']
assert len(combined)==len(set(combined))==4
print({'hybrid_rank':combined,'method':'reciprocal-rank fusion'})
```
