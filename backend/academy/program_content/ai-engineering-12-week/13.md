## The case

A real cited source says only unopened items qualify, but the draft approves an opened item.

## Reason through the decision

Fail factual review despite valid identity; clarify missing conditions or abstain when support is unavailable.

The source exists but contradicts the claim. Separating identity from entailment avoids a common false certificate: valid citations can accompany an unsupported answer. Claim support here is a manual fixture label; semantic judgments need a rubric and evidence, not a confidence string. Applicability also matters: a correct rule for another account or date may still be the wrong answer.

## Vocabulary used in this session

### Citation identity

Referenced IDs exist in the selected authorized evidence.

### Entailment

The actual claim follows from the evidence under its scope.

### Applicability

A rule governs the user, date and conditions of this question.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Citation identity

Citation identity checks whether each cited ID belongs to the selected authorized evidence. It is a useful mechanical gate, but it only proves a reference can be resolved. An answer can cite a real page and say the opposite of that page. Keep citation ID and immutable locator/revision together for inspection.

## Step 2 · Entailment

Entailment asks whether a claim actually follows from the cited evidence. The baseline source permits unopened items; the claim permits opened items, so a reviewer labels it unsupported. Keyword overlap would be high even though meaning is reversed. Break long answers into claims and attach a support decision and evidence for each.

## Step 3 · Applicability

Applicability asks whether a true rule governs this user, date and situation. If the item condition is missing, clarify; if evidence is absent or conflicting, abstain or review. These outcomes differ from answering. An old policy may support a sentence literally while being inapplicable to the active revision.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
retrieved={'p1':'Only unopened items within 14 days qualify.'}
claims=[{'text':'Opened items qualify.','source':'p1','human_support':False}]
identity=all(c['source'] in retrieved for c in claims)
supported=sum(c['human_support'] for c in claims)
assert identity and supported==0
print({'citation_identity':identity,'reviewed_supported_claims':supported,'claims':len(claims),'ready':False})
```
