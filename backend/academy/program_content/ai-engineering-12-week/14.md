## Streaming source-grounded chat with failure states · concepts and decision

## The case

A socket closes after two text chunks and before citation validation.

## Reason through the decision

Keep an incomplete draft, preserve the question and exclude it from the full-answer cache or approved export.

Streaming reduces perceived waiting but exposes provisional output before final validation. The client must render deltas as a draft and wait for a complete event carrying status/source identity. A disconnect after two deltas is not a completed answer and must not enter the full-answer cache. Retrieval-first streaming also needs latency measurement for the silent phase before generation begins.

## Vocabulary used in this session

### Draft delta

Provisional streamed content that has not become a validated result.

### Completion event

An explicit terminal response carrying status and provenance.

### Partial-result policy

How disconnected streams are retained or excluded from cache/export.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Draft delta

A draft delta is a fragment, not a complete answer. Append fragments to a visible draft buffer while retaining the original question. The user can see progress without the application claiming that citations, schema or factual review have finished. Rendering a delta should not mutate the approved-answer store.

## Step 2 · Completion event

A completion event signals the stream reached its normal terminal boundary and carries source IDs/status. Validate those IDs against the authorized evidence before making the result eligible for later review/cache. Completion of generation is not human factual approval; keep those states separate.

## Step 3 · Partial-result policy

A partial-result policy handles disconnect, error and cancellation explicitly. Keep the draft as incomplete, preserve the question and stop sibling work. Never let finally mean successful completion: finally also runs on failures. Full-answer caches should accept only the validated generation-complete state under the correct owner/revision key.

## Walk through the data and state

1. Two delta events build provisional text.

2. Only the third event marks normal generation completion with p1.

3. Removing the last event leaves a partial stream; nonempty text alone cannot complete it.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
import asyncio
async def main():
    events=[];done=False
    async def stream():
        yield {'event':'draft_delta','text':'Unopened '}
        await asyncio.sleep(0)
        yield {'event':'draft_delta','text':'within 14 days.'}
        yield {'event':'draft_complete','source_ids':['p1']}
    async for event in stream():
        events.append(event)
        if event['event']=='draft_complete':done=True
    assert done and events[-1]['source_ids']==['p1']
    partial=events[:-1]
    assert not any(e['event']=='draft_complete' for e in partial)
    print({'partial_is_approved':False,'completed_events':len(events)})
asyncio.run(main())
```
