## The case

A graph waits overnight for review and receives two resume requests after restart.

## Reason through the decision

Persist state durably and consume an authorized version once; in-memory personas do not provide recovery.

Persist state at a meaningful boundary, not only in a conversation buffer. A conditional state/version update prevents a duplicate resume from advancing twice. LangGraph checkpoints use a thread ID to load state; a thread ID is still not authorization. An interrupt can cause a node to execute again on resume, so work before the interrupt must be safe to repeat or isolated in idempotent tasks.

## Vocabulary used in this session

### Checkpoint

A persisted workflow snapshot tied to a controlled execution boundary.

### Thread identity

A state lookup key which does not itself authorize the caller.

### Interrupt replay

Node work may run again on resume and must be safe to repeat.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Checkpoint

A checkpoint stores enough workflow state to resume at a controlled boundary: job ID, owner, state and version. Persist before acknowledging a human pause. The SQLite example closes the connection and reopens the same file to distinguish durable records from process variables. An in-memory graph saver cannot pass a process-restart test.

## Step 2 · Thread identity

A thread/job ID locates state but does not authorize it. A conditional update includes owner as well as ID, expected state and version. rowcount=1 means this request consumed the transition; rowcount=0 means no matching authorized current state existed. Return a controlled conflict/denial rather than silently applying a stale review.

## Step 3 · Interrupt replay

Graph interrupt/resume may rerun node code preceding an interrupt. Place irreversible effects behind a durable, approved dispatcher boundary, not in code that may replay. The optional LangGraph example first demonstrates SDK control flow with an explicitly in-memory saver; the SQL baseline teaches the persistence/version behavior you must retain when choosing a durable checkpointer.

### langgraph_review.py

```python
"""Optional installed-SDK comparison; in-memory checkpoints are not durable.
python langgraph_review.py after installing langgraph in the isolated env.
"""
from typing import TypedDict
from langgraph.graph import StateGraph,START,END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt,Command
class State(TypedDict):
    draft:str
    approved:bool

def review(state:State):
    decision=interrupt({'draft':state['draft'],'question':'Approve this exact draft?'})
    return {'approved':decision is True}

builder=StateGraph(State);builder.add_node('review',review)
builder.add_edge(START,'review');builder.add_edge('review',END)
graph=builder.compile(checkpointer=InMemorySaver())
config={'configurable':{'thread_id':'synthetic-acme-thread-1'}}
first=graph.invoke({'draft':'Unopened within 14 days.','approved':False},config)
assert first.get('__interrupt__')
final=graph.invoke(Command(resume=True),config)
assert final['approved'] is True
print('SDK interrupt/resume passed; persistence and actor authorization must be added separately')
```
