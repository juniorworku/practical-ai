## The case

## Reason through the decision

Parallel delegation can reduce wall time for independent work but also duplicate retrieval, spend and disagreement. Here two workers produce the same claim and double fixture cost without measured quality improvement. ## Vocabulary used in this session

### Coordination overhead

Extra calls, context duplication, communication and failure state.

### Branch provenance

Evidence and results attributable to a specific worker.

### Conflict arbitration

A rule for handling inconsistent delegated results.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Coordination overhead

Coordination overhead includes duplicated prompts, retrieval, model calls, queueing and state. Two workers can reduce wall time only when work can overlap meaningfully. Keep a single-workflow baseline with the same input and quality bar. Compare total accepted-output spend, not only the fastest branch.

## Step 2 · Branch provenance

Branch provenance records who produced a claim, from which source/revision, with what outcome and cost. Agreement between two workers using the same source is not independent verification. Deduplicate claims for presentation, while retaining both calls in cost accounting and both provenance records for debugging.

## Step 3 · Conflict arbitration

Conflict arbitration determines what happens when branches disagree. Do not concatenate incompatible claims or count votes without evidence. A safe first policy is review when distinct supported claims conflict. LangChain, LangGraph and CrewAI organize composition, state or roles differently; adopt one only after the simpler baseline exposes a concrete requirement.

## Predict before execution

Save this entire block as example.py in an empty directory. Run `python3 -I example.py` with assertions enabled. It uses only the Python standard library, includes its synthetic data and performs no provider calls. Explain each assertion before running.

```python
import asyncio
async def branch(name):
    await asyncio.sleep(0)
    return {'branch':name,'source':'p1','claim':'Only unopened items','cost':2}
async def main():
    results=await asyncio.gather(branch('policy'),branch('account'))
    claims={r['claim'] for r in results}
    total=sum(r['cost'] for r in results)
    assert len(results)==2 and len(claims)==1 and total==4
    print({'workers':2,'unique_claims':len(claims),'total_cost':total,'quality_gain_not_established':True})
asyncio.run(main())
```

### Latency vs. Cost vs. Quality

Compare a fixed plan, bounded graph and delegated tasks. Include all tool/model calls, handoff delays and human review in the useful-output denominator.

### Deterministic Evaluation

Replay duplicate events, stale approvals, denied scopes, graph resumes and lost responses. Assert one authorized state transition; separately reconcile remote effects.

### Context Management

Persist bounded state outside the prompt. Select tenant-scoped memory, budget tool results and invalidate approval/cache when effect fields or source revisions change.

## Failure and deployment work

Verify connector scopes and actor identity outside model output, bind approval to the exact payload and destination, and handle timeout outcomes as uncertain.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
