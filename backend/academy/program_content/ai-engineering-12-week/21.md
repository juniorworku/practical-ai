## MCP hosts, clients, servers and tool contracts · concepts and decision

## The case

A newly discovered MCP tool claims it can read every workspace file.

## Reason through the decision

Treat the description as untrusted capability metadata; expose only authorized resources and validate invocations.

MCP separates a host, per-server clients and capability-providing servers. Discovery describes tools/resources/prompts; it does not authorize all discovered behavior. Validate negotiated capabilities and schema at invocation, scope credentials to the actual server and enforce the authenticated owner in the tool implementation. This JSON fixture is a discovery-contract check, not a complete MCP server or handshake.

## Vocabulary used in this session

### MCP host

The application managing clients, permissions and model interaction.

### Capability discovery

Negotiated descriptions of supported tools/resources/prompts.

### Invocation boundary

Validation and authority checks around an actual tool call.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · MCP host

The MCP host is the user-facing application coordinating model interaction and permissions. It maintains clients that connect to servers. A server exposes bounded capabilities such as a policy lookup; it is not automatically the host or the authenticated end user. Keep credentials and resource scope attached to the actual connection.

## Step 2 · Capability discovery

Capability discovery reports what a server says it can provide: tools, resources or prompts. Initialization negotiates protocol support before discovery/invocation. Descriptions may be untrusted, and discovering a tool does not grant permission to use it. The baseline JSON object illustrates a discovery result only; the supplied SDK client/server demonstrates a real initialization and stdio round trip.

## Step 3 · Invocation boundary

The invocation boundary validates the chosen tool, argument schema, authenticated owner and returned data. An argument named owner does not authenticate anyone. Restrict filesystem or connector access in server code, and validate results before using them as model context. Transport support and cancellation behavior must be tested per server.

### mcp_policy.py

```python
"""Local stdio MCP teaching server; server-scoped single synthetic tenant.
Register: command python, arguments absolute path to this file.
No credentials, no arbitrary filesystem tool, no messaging effects.
"""
from mcp.server.fastmcp import FastMCP
server=FastMCP('Synthetic policy reader')
POLICIES={'returns-v1':'Unopened items within 14 days; opened items excluded.'}
@server.tool()
def lookup_policy(policy_id:str)->dict:
    """Read an allowlisted synthetic policy; no writes or filesystem paths."""
    if policy_id not in POLICIES:return {'status':'not_found'}
    return {'status':'found','id':policy_id,'text':POLICIES[policy_id]}
if __name__=='__main__':server.run(transport='stdio')
```

### mcp_client.py

```python
"""Run beside mcp_policy.py after installing the supplied dependencies."""
import asyncio, sys
from pathlib import Path
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
async def main():
    params=StdioServerParameters(command=sys.executable,args=[str(Path(__file__).with_name('mcp_policy.py'))])
    async with stdio_client(params) as (reader,writer):
        async with ClientSession(reader,writer) as session:
            await session.initialize()
            tools=await session.list_tools()
            assert [t.name for t in tools.tools]==['lookup_policy']
            result=await session.call_tool('lookup_policy',{'policy_id':'returns-v1'})
            assert not result.isError
            assert '14 days' in result.content[0].text
            print(result.model_dump_json())
asyncio.run(main())
```
