## Vocabulary used in this session

### Admission control

Rejecting work before exceeding a bounded resource budget.

### Atomic shared quota

Cross-replica accounting with defined failure/reconciliation behavior.

### Fallback contract

An evaluated alternative preserving authority, data and response constraints.

## Learn each concept step by step

Read these three explanations before running the specimen. Each connects a definition to the decision it controls.

## Step 1 · Admission control

Admission control checks resources before expensive provider work. A request-rate bucket is distinct from simultaneous worker capacity, a token reservation and a monthly monetary budget. Two cheap short calls and two long generations can have the same request count but very different cost. Keep these limits explicit and report rejection.

## Step 2 · Atomic shared quota

An atomic shared quota means all workers update the same allowance as one indivisible operation. Separate local buckets each starting with two tokens can admit four aggregate requests. A durable conditional update or suitable shared-store primitive can enforce a global bound. Choosing shared state is not enough if check and decrement are separate races.

## Step 3 · Fallback contract

A fallback contract preserves authorization, permitted data location, output shape, deadline and evaluated quality. A failed quota store should follow an explicit fail-closed or bounded degraded policy; unlimited fallback can destroy the budget. Reserve estimated usage before work and reconcile actual usage afterward without double-refunding retried operation keys.

```python
# Single-process token-bucket fixture. Replicas need a shared atomic store.
class Bucket:
    def __init__(self,capacity,refill):self.capacity=capacity;self.tokens=capacity;self.refill=refill;self.last=0
    def take(self,now,amount=1):
        self.tokens=min(self.capacity,self.tokens+(now-self.last)*self.refill);self.last=now
        if amount>self.tokens:return False
        self.tokens-=amount;return True
bucket=Bucket(2,1)
assert bucket.take(0) and bucket.take(0) and not bucket.take(0)
assert bucket.take(1)
print('burst bounded; one request admitted after refill; shared atomic store still required')
```

## Apply the three pillars to A multi-user AI service deployed from containers

### Latency vs. Cost vs. Quality

Load-test offered vs. completed work, p95 and cost per accepted result at stated concurrency. Autoscaling settings are hypotheses until observed against downstream/GPU limits.

### Deterministic Evaluation

Test readiness against the actual database, restart/readback, isolated restore, denied owner access, overload rejection and a dependency outage on the deployed revision.

### Context Management

Budget resident model memory/KV cache and per-request context separately. Keep tenant/revision-aware application caches; never assume a process-local cache is shared across replicas.

## Failure and deployment work

Separate request concurrency, worker capacity and model/GPU capacity. Add admission control, shared quotas, bounded queues, maximum instances and a documented fallback/stop budget.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
