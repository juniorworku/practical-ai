## Why this decision matters

Document extraction is a data-modeling problem before it is a prompting problem. Decide which fields are required, which may be unknown, and which need review. A missing field, a zero value, and an unreadable field are different states. Preserve a link to the source excerpt so a reviewer can audit each extracted value.

Start with synthetic purchase requests rather than private invoices. Define currencies and dates explicitly. A model should not invent a due date because the schema requires one. If an external action depends on a value, validate it independently and require review when uncertainty changes the decision. Your output is a draft record, not an approved purchase.

## Vocabulary used in this session

### Extraction schema

A definition of fields, allowed types, unknown states and review requirements.

### Unknown value

A field the source does not establish, distinct from zero or a guessed default.

### Evidence span

The source text supporting a particular extracted field.

## Worked implementation: Model the document before automating it

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
source = 'Order 2 seats at 12.50 each.'
record = {'quantity':2,'unit_price':'12.50','currency':None,'due_date':None,
          'evidence':{'quantity':'2 seats','unit_price':'12.50 each'},
          'review_reasons':['currency absent','due date absent']}
assert all(span in source for span in record['evidence'].values())
assert record['currency'] is None and record['due_date'] is None
assert record['review_reasons']
print(record)
```

## Expected observation

```text
{'quantity': 2, 'unit_price': '12.50', 'currency': None, 'due_date': None, 'evidence': {'quantity': '2 seats', 'unit_price': '12.50 each'}, 'review_reasons': ['currency absent', 'due date absent']}
```

## Walk through the mechanism and its limits

The record is manually labeled, not extracted by a model. It establishes a schema and an answer sheet before automation. Evidence spans point to exact text; nullable values represent absent facts rather than zero or a guessed default. Span membership is only a first check: an old quoted price may also occur in the source without being the current price.

## Worked example

A fictional request says “Please order 12 units at 25 each; delivery next month.” Quantity and unit price are available; currency and an exact delivery date are not. Store `currency: null`, a review reason, and the supporting text. Do not silently assume USD or the first day of the month.

## Break it deliberately
