## Why this decision matters

Separate extraction, normalization, validation, and review. Extraction identifies candidate values; normalization converts formats; validation checks consistency; review resolves uncertainty. Keeping stages distinct lets you diagnose whether a wrong total came from reading the document or from arithmetic.

Use decimal arithmetic for money-like values and do not let generated text perform authoritative calculations. Validate types and ranges before downstream use. Keep the raw field beside the normalized field so parsing decisions remain inspectable. A fake extraction adapter makes this pipeline testable offline, while a later real provider can be compared using the same fixtures.

## Vocabulary used in this session

### Normalization

Converting a known raw representation into an explicitly supported canonical format.

### Deterministic validation

Using code to enforce type, range and consistency rules.

### Quarantine

Keeping an invalid draft separate with reasons instead of silently accepting it.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Normalization

Normalization translates a documented representation into a canonical value while preserving raw input. Accepting a known decimal comma format can be reasonable; guessing whether 1,234 means a decimal or thousands is not. Separate source-format normalization from business validation so failures can be diagnosed at the right stage.

## Step 2 · Deterministic validation

Deterministic validation checks types and arithmetic under explicit rules. Decimal avoids binary floating-point surprises for money; exact integer type checking rejects True as a quantity. Compare unit price times quantity to total, and keep missing currency distinct from a total mismatch. Passing arithmetic does not prove the extracted fields came from the source.

## Step 3 · Quarantine

Quarantine retains input, raw values and error reasons when a record cannot advance. It is not deletion. A reviewer should see whether the issue is ambiguous format, invalid quantity or conflicting total and make a recorded correction. Revalidate that correction instead of allowing review to bypass every invariant.

## Walk through the data and decision

1. money permits only a nonnegative two-decimal string.

2. validate rejects True quantity and a mathematically inconsistent total.

3. Invalid amounts and currency-review errors have distinct categories.

```python
from decimal import Decimal, InvalidOperation
import re
def money(raw):
    if type(raw) is not str or not re.fullmatch(r'[0-9]+[.][0-9]{2}',raw):
        raise ValueError('use an explicit nonnegative decimal with two places')
    number=Decimal(raw)
    if not number.is_finite(): raise ValueError('nonfinite')
    return number
def validate(record):
    errors=[]
    q=record.get('quantity')
    if type(q) is not int or q<=0: errors.append('quantity:invalid')
    try: price,total=money(record.get('unit_price')),money(record.get('total'))
    except (ValueError,TypeError,InvalidOperation): return errors+['amount:invalid']
    if not errors and price*q != total: errors.append('total:mismatch')
    if record.get('currency') not in {'USD','EUR'}: errors.append('currency:review')
    return errors
valid={'quantity':2,'unit_price':'12.50','total':'25.00','currency':'USD'}
assert validate(valid)==[]
assert validate(dict(valid,total='24.00'))==['total:mismatch']
assert 'quantity:invalid' in validate(dict(valid,quantity=True))
for value in ['-1.00','NaN','1,25',None]:
    assert 'amount:invalid' in validate(dict(valid,unit_price=value))
print('valid record accepted; mismatched total, boolean quantity and ambiguous amounts rejected')
```

## Walk through the mechanism and its limits

Decimal preserves exact decimal arithmetic for the deliberately narrow supported format. Exact type checks reject Python booleans, which otherwise behave like integers. Validation reports an inconsistency but never rewrites the source to make arithmetic agree. Unsupported formats stop for review; the two-currency allowlist is an exercise boundary, not a global currency catalog.

## Step 1 · Keep source evidence before normalizing

enumerate(..., 1) assigns human-readable line numbers. split(":", 1) separates only the first colon, so a supplier name containing a colon stays intact. Each field retains the complete raw line and the trimmed value. The normalized record is useful for computation; the source span is needed to inspect whether that value was actually present. A line number is meaningful only alongside this exact submitted text, retained in the final API draft.

## Step 2 · Treat duplicates as ambiguity, not last-write wins

Two Quantity lines are not permission to choose the last one. evidence stores both spans; fields keeps the first value only for diagnostics, and issues forces needs_correction. No record is emitted from that branch. Even two identical repeated values are flagged, because this fixed schema permits one occurrence. A schema that supports repeated line items needs a different declared contract and evaluation cases.

## Step 3 · Validate before doing arithmetic

The schema requires exactly Supplier, Quantity, Unit price and Currency. Quantity must be an ASCII integer from 1 to 1000. Unit price must have exactly two decimal places and supported currency is USD. Decimal constructs an exact base-ten amount from the validated string; float can introduce binary rounding error. Missing price, NaN and negative quantities route to correction rather than becoming zero, guesses or a purchase order.

## Step 4 · Trace the success and correction branches

For Quantity 2 and Unit price 10.00, predict total 20.00 and line 2 as the quantity source. Add Quantity 9 on line 5: both spans survive, but text is null and status needs_correction. Confirmation is a later workflow step, not an extraction accuracy claim. In the final capstone, field_evidence and original input are saved with the same draft; a local reviewer checks them before approval. No OCR, model call or real order occurs.

```python
"""Purchase-request extraction: explicitly deterministic parsing, not AI extraction."""
from decimal import Decimal
import re
KIND='workshops'
VERSION='purchase-schema-v2'
def process(text,mode,documents):
 if mode=='timeout':raise TimeoutError('fixture')
 if mode=='malformed':raise ValueError('fixture_invalid_output')
 fields={};issues=[];evidence={}
 for number,line in enumerate(text.splitlines(),1):
  if not line.strip():continue
  if ':' not in line:issues.append('unrecognized_line');continue
  key,value=line.split(':',1);key=key.strip().lower()
  evidence.setdefault(key,[]).append({'line':number,'raw':line,'value':value.strip()})
  if key in fields:
   issues.append('duplicate_'+key)
   continue  # Retain both spans, but never silently overwrite the first value.
  fields[key]=value.strip()
 required={'supplier','quantity','unit price','currency'}
 if set(fields)!=required:issues.append('missing_or_extra_fields')
 if not fields.get('supplier'):issues.append('supplier_required')
 quantity=fields.get('quantity','')
 if not quantity.isascii() or not quantity.isdigit() or not 1<=int(quantity)<=1000:issues.append('quantity_integer_1_to_1000')
 price=fields.get('unit price','')
 if not re.fullmatch(r'\d{1,6}\.\d{2}',price):issues.append('unit_price_two_decimals')
 if fields.get('currency')!='USD':issues.append('currency_not_supported')
 if issues:return {'status':'needs_correction','text':None,'citations':[],'issues':issues,'field_evidence':evidence,'trace':['parse','validate','manual_correction']}
 total=Decimal(price)*int(quantity)
 # A source excerpt, never an invented missing field or a silent zero.
 result={'supplier':fields['supplier'],'quantity':int(quantity),'unit_price':price,'currency':'USD','total':str(total)}
 return {'status':'needs_review','text':str(result),'record':result,'field_evidence':evidence,'citations':['submitted-request'],'context_chars':len(text),'trace':['parse','validate','calculate','await_confirmation']}

text='Supplier: Studio\nQuantity: 2\nUnit price: 10.00\nCurrency: USD'
result=process(text,'fixture',[])
assert result['record']['total']=='20.00'
assert result['field_evidence']['quantity'][0]['line']==2
conflict=process(text+'\nQuantity: 9','fixture',[])
assert conflict['status']=='needs_correction'
assert [s['value'] for s in conflict['field_evidence']['quantity']]==['2','9']
print('USD20.00 traced to input lines; conflicting quantity retained for correction')
```
