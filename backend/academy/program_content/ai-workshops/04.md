## Understand the decision: Distinguish statements, decisions, and commitments

## Before you begin

This is studio 2. Begin with basic Python functions, dictionaries and assertions; the specimen below supplies all its data. No other academy program or paid model account is required.

## Why this decision matters

Meeting summarization becomes useful when it preserves who committed to what, by when, and with what dependencies. A suggestion is not a decision, and a mentioned person is not necessarily an owner. Capture unknown ownership explicitly. Use evidence spans so participants can challenge a proposed action without rereading the entire transcript.

The project uses invented meeting notes. In a real setting, recording consent, organizational policy, access control, and retention would shape the design. This workshop does not assume permission to record anyone or upload a real transcript. Build the workflow using the minimum data needed to test the concept.

## Vocabulary used in this session

### Suggestion

A possible action that has not been confirmed as a commitment.

### Commitment

An action explicitly accepted by an identifiable owner.

### Date anchor

The reference date required to interpret relative time expressions.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Suggestion

A suggestion proposes work without establishing that somebody accepted responsibility. “Maybe Sam can review” must not become Sam’s commitment merely because the name appears. Annotate the statement type and source span before adding extraction automation. Keep suggestions visible as unresolved proposals rather than deleting them from the meeting record.

## Step 2 · Commitment

A commitment has evidence of acceptance, but later retraction or reassignment can supersede it. Process statements in source order and preserve the earlier evidence. If David is proposed but has not accepted, the owner remains unresolved. The fixture uses prepared event labels, so it tests update policy rather than understanding raw conversation.

## Step 3 · Date anchor

A date anchor interprets relative wording using a known meeting date, timezone and convention. “Friday” can mean this or next Friday; state the rule and ask for clarification when necessary. The baseline explicitly uses the next occurrence including today. Store unresolved dates as unknown, not the date your computer happens to show.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
from datetime import date, timedelta
transcript=[{'id':'s1','kind':'suggestion','owner':'Sam','text':'Maybe Sam can review'},
            {'id':'s2','kind':'accept','owner':'Sam','text':'I will review on Friday'},
            {'id':'s3','kind':'retract','owner':'Sam','text':'I cannot; leave owner unresolved'}]
def register(events):
    result={'owner':None,'state':'unconfirmed','evidence':[]}
    for event in events:
        result['evidence'].append(event['id'])
        if event['kind']=='accept': result.update(owner=event['owner'],state='confirmed_in_transcript')
        if event['kind']=='retract': result.update(owner=None,state='unconfirmed')
    return result
result=register(transcript)
assert result['owner'] is None and result['evidence']==['s1','s2','s3']
meeting=date(2026,10,20)
# Explicit exercise convention: next occurrence, including today.
friday=meeting+timedelta(days=(4-meeting.weekday())%7)
assert friday.isoformat()=='2026-10-23'
print({'register':result,'anchored_friday':friday.isoformat()})
```

## Walk through the mechanism and its limits

The events are human annotations, not an NLP parser. Applying them in order preserves the later retraction; extracting only the first name would invent ownership. Transcript commitment is distinct from later application confirmation. Relative dates need an anchor and an explicit convention: “next Friday” can have multiple interpretations, so ask when the convention is uncertain.
