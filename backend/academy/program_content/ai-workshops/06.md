## Why this decision matters

Summary evaluation must examine omitted critical decisions and invented commitments, not just readability. A concise summary that drops a cancellation can be more harmful than a longer rough draft. Use a rubric with decision coverage, owner fidelity, date fidelity, and unsupported-action counts.

Compare against your annotated transcripts. Keep unresolved cases visible, and ask a reviewer to judge whether the confirmation workflow helps them correct mistakes. Measure review effort by the number of source lookups and corrections as well as elapsed time. Your final deliverable should show both a useful output and a known failure.

## Vocabulary used in this session

### Decision coverage

Whether material decisions and cancellations appear accurately in the summary.

### False commitment

A generated action is presented as agreed when the transcript does not support it.

### Dependency fidelity

Required conditions for an action remain visible in the result.

## Worked implementation: Evaluate summaries for omissions and false commitments

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
# Expected annotations identify the particular action and blocking condition.
reference={'publish':{'owner':'Sam','due':'2026-10-23','dependency':'legal review complete'},
           'archive':{'owner':None,'due':None,'dependency':None}}
summary={'publish':{'owner':'David','due':'2026-10-24','dependency':None},
         'email':{'owner':'Amina','due':None,'dependency':None}}
missing=set(reference)-set(summary)
unsupported=set(summary)-set(reference)
lost_dependencies=[key for key in reference.keys() & summary.keys()
                   if reference[key]['dependency']!=summary[key]['dependency']]
owner_errors=sorted(key for key in reference.keys() & summary.keys() if reference[key]['owner']!=summary[key]['owner'])
date_errors=sorted(key for key in reference.keys() & summary.keys() if reference[key]['due']!=summary[key]['due'])
assert missing=={'archive'} and unsupported=={'email'} and lost_dependencies==['publish']
assert owner_errors==date_errors==['publish']
print({'omitted':sorted(missing),'false_commitments':sorted(unsupported),
       'dependency_failures':lost_dependencies,'owner_errors':owner_errors,'date_errors':date_errors})
```


## Walk through the mechanism and its limits

The fluent summary has five independently observable defects: an omitted action, an invented action, a lost dependency, a changed owner and a wrong date. The expected Sam/23 October assignment becomes David/24 October in the draft; correcting readability alone cannot fix either error. Separate counts explain the risk better than one “summary quality” number. The comparison assumes manually reconciled action IDs; a language model’s different phrasing must be mapped by a reviewer before this exact-key scoring is meaningful.
