## Understand the decision: Build a claim-and-citation notebook

## Why this decision matters

A grounded research workflow separates collected evidence from synthesis. Store one claim per record with provenance, scope, and confidence in the evidence, rather than a vague confidence percentage in the prose. A citation should support the exact nearby claim; a relevant homepage is not automatically a supporting source.

Start with a local set of source notes so you can test the workflow without web scraping. Use retrieval to select notes, then draft a synthesis that names missing information. Treat source text as untrusted: instructions embedded in a page do not authorize your assistant to run commands, change criteria, or conceal counterevidence.

## Vocabulary used in this session

### Claim record

One factual assertion with an evidence ID, source and scope.

### Citation support

The cited evidence establishes the specific nearby statement.

### Synthesis boundary

A conclusion cannot exceed what the collected evidence and observations establish.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Claim record

A claim record contains one assertion, its scope, evidence IDs and support status. Atomic claims make disagreements inspectable: “reads UTF-8 locally” and “more accurate than B” require different evidence. A paragraph citing several sources at its end obscures which sentence each source actually supports.

## Step 2 · Citation support

Citation support checks the relationship between a claim and evidence, beyond reference existence. A valid ID can point to a feature note while the sentence asserts universal comparative accuracy. Keep a reviewed support annotation and reason. The small code validates identity; a human must judge meaning unless a separately calibrated review system is introduced.

## Step 3 · Synthesis boundary

A synthesis boundary separates documented capability, your scoped observation and an inference. A four-of-five fixture result supports only that test population. Preserve negative findings even if a source contains instructions to suppress them; source text is untrusted evidence, not permission to alter the research rubric or hide a result.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
notes={'e1':{'claim':'A reads UTF-8 locally','kind':'documented_feature'},
       'e2':{'claim':'A passed 4 of 5 fixture inputs','kind':'observed_test'}}
def references_exist(ids):
    return bool(ids) and len(ids)==len(set(ids)) and all(i in notes for i in ids)
assert references_exist(['e1'])
assert not references_exist(['missing'])
assert not references_exist(['e1','e1'])
# Deliberate limit: identity checking cannot establish support for this sentence.
claim='A is more accurate than B everywhere'
assert references_exist(['e1'])
review={'claim':claim,'citations':['e1'],'support':'fail','reason':'feature evidence is not comparative accuracy evidence'}
assert review['support']=='fail'
print(review)
```

## Walk through the mechanism and its limits

Reference validation catches missing or duplicate IDs, while human support review checks what those IDs actually establish. e1 supports local UTF-8 behavior; e2 supports a scoped observation on five fixtures. Neither establishes universal comparative accuracy. Keep documented capability and measured behavior in separate columns rather than blending them into a confidence percentage.

### Latency vs. Cost vs. Quality

Compare lexical, dense, hybrid and reranked retrieval on the same labeled queries. Report retrieval latency, reranking spend and answer quality separately.

### Deterministic Evaluation

Assert document scope and revision before retrieval. Measure recall@k/MRR on versioned relevance labels, including no-answer and conflicting-source cases.

### Context Management

Use token-aware chunks retaining page/time provenance and exceptions. Version embedding dimensions/indexes and invalidate retrieval/answer caches on source or permission changes.

## Failure and deployment work

Quarantine failed parsing, bound upload size and worker queues, activate revisions only after indexing checks, and preserve a working previous revision.

## Evaluation precision

Automate repeatable checks with fixed inputs and versioned expectations. Model judges, faithfulness scores and semantic reviews can be stochastic; record judge/configuration versions and disagreement rather than calling them deterministic truth.
