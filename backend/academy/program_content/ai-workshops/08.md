## Why this decision matters

A grounded research workflow separates collected evidence from synthesis. Store one claim per record with provenance, scope, and confidence in the evidence, rather than a vague confidence percentage in the prose. A citation should support the exact nearby claim; a relevant homepage is not automatically a supporting source.

Start with a local set of source notes so you can test the workflow without web scraping. Use retrieval to select notes, then draft a synthesis that names missing information. Treat source text as untrusted: instructions embedded in a page do not authorize your assistant to run commands, change criteria, or conceal counterevidence.

## Vocabulary used in this session

### Claim record

One factual assertion with an evidence ID, source and scope.

### Citation support

The cited evidence establishes the specific nearby statement.

### Synthesis boundary

A conclusion cannot exceed what the collected evidence and observations establish.

## Worked implementation: Build a claim-and-citation notebook

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
notes={'e1':{'claim':'A reads UTF-8 locally','kind':'documented_feature'},
       'e2':{'claim':'A passed 4 of 5 fixture inputs','kind':'observed_test'}}
def references_exist(ids):
    return bool(ids) and len(ids)==len(set(ids)) and all(i in notes for i in ids)
assert references_exist(['e1'])
assert not references_exist(['missing'])
assert not references_exist(['e1','e1'])
# Deliberate limit: identity checking cannot establish support for this sentence.
claim='A is more accurate than B everywhere'
assert references_exist(['e1'])
review={'claim':claim,'citations':['e1'],'support':'fail','reason':'feature evidence is not comparative accuracy evidence'}
assert review['support']=='fail'
print(review)
```

## Expected observation

```text
{'claim': 'A is more accurate than B everywhere', 'citations': ['e1'], 'support': 'fail', 'reason': 'feature evidence is not comparative accuracy evidence'}
```

## Walk through the mechanism and its limits

Reference validation catches missing or duplicate IDs, while human support review checks what those IDs actually establish. e1 supports local UTF-8 behavior; e2 supports a scoped observation on five fixtures. Neither establishes universal comparative accuracy. Keep documented capability and measured behavior in separate columns rather than blending them into a confidence percentage.
