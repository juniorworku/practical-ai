## Understand the decision: Run a small benchmark and write a decision memo

## Why this decision matters

A benchmark is only meaningful when candidates receive comparable inputs, settings, and measurement rules. Define the dataset and scoring before running it. Record environment and version information. A tiny benchmark is useful for a local decision, but it does not establish universal superiority.

Combine observed results with documented constraints. If one tool performs better but cannot run in your required environment, that constraint matters. Explain how weights or missing evidence affect the decision. Your reader should be able to disagree with a weight and see how the conclusion changes.

## Vocabulary used in this session

### Controlled comparison

Candidates receive the same representative inputs and defined measurement rules.

### Sensitivity analysis

Recomputing a decision when priorities or assumptions change.

### Benchmark scope

The conditions and dataset to which observed performance results apply.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Controlled comparison

A controlled comparison keeps inputs, scoring, versions and conditions fixed across candidates. The fixture tests exact preservation, so losing an accent is an error. A different task might permit normalization, but that rule must be declared before running. Keep failed executions in the denominator and record timing separately from correctness.

## Step 2 · Sensitivity analysis

Sensitivity analysis asks whether the recommendation changes when plausible weights, error costs or workloads change. First apply hard constraints such as offline operation. Weighted scores must not allow a cheap online-only candidate to buy its way past a mandatory offline requirement. Compare eligible candidates and state the assumptions driving the final choice.

## Step 3 · Benchmark scope

Benchmark scope limits what the observed sample supports. Two toy parser functions and three inputs are not product evidence. A decision memo should name the version, fixture population, failures and missing criteria, then propose the next discriminating test. Never reuse the illustrative scores as claims about a real vendor.

## Worked implementation: Run a small benchmark and write a decision memo

## Walk through the data and decision

1. A and B receive identical accented, multiline and empty inputs.

2. B changes one input and fails another; all three remain recorded.

3. The exact-preservation rule produces A 3/3 and B 1/3 only for these toy functions.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
fixtures={'d1':'café','d2':'two lines\nremain','d3':''}
def parser_a(text): return text
def parser_b(text):
    if not text: raise ValueError('empty unsupported')
    return text.replace('é','e')
results={}
for name, parser in [('A',parser_a),('B',parser_b)]:
    rows=[]
    for identifier,text in fixtures.items():
        try:
            output=parser(text)
            rows.append({'id':identifier,'ran':True,'exact':output==text})
        except ValueError:
            rows.append({'id':identifier,'ran':False,'exact':False})
    results[name]=rows
assert sum(r['exact'] for r in results['A'])==3
assert sum(r['exact'] for r in results['B'])==1
assert len(results['B'])==3
print({name:{'exact':sum(r['exact'] for r in rows),'total':len(rows)} for name,rows in results.items()})
```

## Expected observation

```text
{'A': {'exact': 3, 'total': 3}, 'B': {'exact': 1, 'total': 3}}
```

## Walk through the mechanism and its limits

These are toy parser functions, not benchmarks of named products. Both see identical inputs and exact-preservation scoring. B changes the accented character and fails empty input; its failed run stays in the denominator. Exact equality is useful for this preservation criterion, but would be wrong if approved normalization were intended. Define that choice before running.
