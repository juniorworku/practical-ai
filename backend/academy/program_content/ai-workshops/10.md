## Understand the decision: Design a taxonomy with an uncertainty route

## Why this decision matters

Classification automates a decision boundary. Define categories by the downstream action they enable, not merely by similar wording. A category is useful when its definition and examples help two people agree on the right handling. Include an uncertainty or review route when input does not establish a safe choice.

This project routes fictional support messages without sending replies or changing customer records. Urgency and topic are separate fields. A complaint about a delayed shipment may be a shipping topic and a normal priority; an account compromise may require an urgent human response regardless of tone. Avoid using sentiment as a substitute for operational severity.

## Vocabulary used in this session

### Taxonomy

Explicit categories defined by meaningful downstream handling.

### Multi-intent input

A message contains more than one relevant task or topic.

### Urgency

Operational severity assessed separately from topic or writing tone.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Taxonomy

A taxonomy defines labels, inclusion/exclusion rules and an uncertainty route before classification. Billing and account are different topics from urgency. Prepare annotated examples that stress boundaries rather than assigning a label from one keyword. Keep the allowed next action separate so a routing label cannot authorize a refund.

## Step 2 · Multi-intent input

Multi-intent input contains more than one material task. A message about a duplicate charge and account compromise should not silently lose one issue. The baseline routes multiple topics to review. A real system may split work, but that requires linked records and explicit ownership so neither issue disappears during handoff.

## Step 3 · Urgency

Urgency reflects consequence and time sensitivity, not angry tone. A polite compromise report may be urgent while a complaint containing “urgent” may not be. The fixture receives manually annotated features; it does not prove a keyword classifier can infer those features. Evaluate annotation disagreements before comparing classification implementations.

## Worked implementation: Design a taxonomy with an uncertainty route

## Walk through the data and decision

1. The topic set excludes politeness and compromise from topic labels.

2. Multiple material topics yield review rather than arbitrary selection.

3. compromise independently raises urgency even when polite is present.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
def classify(tags):
    # tags are manually annotated features, not a language-understanding system.
    topics=set(tags) & {'billing','shipping','account','product','other'}
    urgency='urgent' if 'compromise' in tags else 'normal'
    route=next(iter(topics)) if len(topics)==1 else 'review'
    return {'topics':sorted(topics),'urgency':urgency,'suggested_queue':route}
assert classify({'billing','account'})['suggested_queue']=='review'
assert classify({'account','compromise','polite'})['urgency']=='urgent'
assert classify(set())['suggested_queue']=='review'
print(classify({'billing','account','polite'}))
```

## Expected observation

```text

```

## Walk through the mechanism and its limits

The input is an annotated feature set so the handling policy can be evaluated before NLP. Topic answers what kind of work; urgency answers its consequence and time sensitivity. Multiple material topics route to review instead of arbitrarily discarding one. A keyword detector added later will have its own errors and cannot inherit the correctness of these manually supplied tags.
