# Routing rules, confusion matrices, and fallback

## The engineering or business decision

A confusion matrix shows which categories are being mistaken for which others. Overall accuracy can hide a dangerous pattern when one category is rare. Establish a deterministic baseline first, then compare a model-based or hybrid classifier against the same labeled messages.

Fallback behavior is part of the classifier. Unknown outputs should not become a default operational action. A valid category string still needs permission checks before any write occurs. Keep automatic actions disabled in this project; the result is a suggested queue and explanation using observable features or evidence, followed by human review.

## Worked example

A rules baseline sends messages containing “password” to account access. It misroutes “Do not reset my password; where is my package?” Inspect that failure rather than adding unbounded keyword patches. Compare per-topic precision and recall, and keep a review queue for unresolved cases.

## Break it deliberately

The classifier emits an unknown label such as `urgent-refund-approved`. Treat it as invalid output, not a new authorized workflow.

## Acceptance checks

- Metrics include per-category counts.
- Invalid classifier output is routed to review.
- The comparison identifies at least two distinct error types.
