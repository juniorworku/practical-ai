# Draft, critique, and revise with a rubric

## The engineering or business decision

A critique loop needs criteria and a stopping rule. Otherwise it produces endless stylistic changes that do not improve usefulness. Separate factual review from clarity, accessibility, and tone. Use a maximum number of revisions and require a human to resolve factual disputes.

Compare drafts against the same rubric rather than asking a model whether it likes its own output. An automated reviewer can suggest problems, but it cannot certify facts absent from evidence. Preserve the initial draft, review notes, and revision so you can explain the effect of a change.

## Worked example

Your rubric checks whether the reader can complete CSV export, whether each step is supported, whether jargon is explained, and whether limitations are visible. A shorter draft that removes the only instruction for selecting a file is a regression even if it sounds cleaner.

## Build it yourself

1. Create a rubric with factual support, task completeness, clarity, and accessibility criteria.
2. Produce two drafts using the same brief, manually or with an optional provider.
3. Review both against the rubric and revise once based on specific findings.
4. Record changes that improved task completion and changes you rejected.

## Break it deliberately

The critique suggests a feature that does not exist. Reject that suggestion and retain the fact boundary through the revision loop.

## Acceptance checks

- Review findings cite a passage or missing requirement.
- The revised draft stays within the fact sheet.
- The loop has an explicit stopping point.
