## Understand the decision: Design a responsible publishing workflow

## Why this decision matters

Publishing adds an external effect to a drafting workflow. Treat it as a separate permissioned step. Keep preview, approval, publication, and rollback states distinct. An approval should identify the exact content revision and destination; editing the draft invalidates that approval.

Use a local mock publishing directory for this studio. It demonstrates workflow behavior without posting publicly or messaging anyone. Check links, factual claims, accessible headings, and personal data before review. A content workflow should make it easy to retract a mistaken version and identify which readers or destinations were affected.

## Vocabulary used in this session

### Publication approval

Authorization for a particular content revision and destination.

### Content hash

A fingerprint that helps identify whether approved content has changed.

### Withdrawal record

An auditable state showing a published version has been removed or superseded.

## Learn each concept step by step

Work through these explanations before the completed example or exercise. Follow the inputs, mechanism and decision boundary rather than memorizing the definitions.

## Step 1 · Publication approval

Publication approval covers exact content, destination and current authority. A reviewer approving preview.txt has not approved another public channel. Recheck immediately before publishing and treat edits as new review work. The fixture writes only a local mock artifact; it provides no real external publication credentials or remote guarantees.

## Step 2 · Content hash

A content hash fingerprints the approved bytes. It detects even a small date change but does not encrypt the text, prove authorship or show the reviewer had authority. Combine it with destination, revision and expiry. An unchanged approved artifact can be recognized to suppress duplicate local publication records.

## Step 3 · Withdrawal record

A withdrawal record preserves what was removed, why and when while retracting the published artifact. Deleting history destroys incident evidence. Restoring an earlier version also needs specific approval; “previously approved once” does not authorize any future destination or edited content. Persist the manifest and audit in the real application.

## Worked implementation: Design a responsible publishing workflow

## Walk through the data and decision

1. Edited content and a changed destination both return needs_review.

2. The exact approved local artifact publishes once and repeats as already_published.

3. Withdrawal removes the file while retaining published and withdrawn audit events.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`. No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import hashlib, json
def digest(text): return hashlib.sha256(text.encode()).hexdigest()
with TemporaryDirectory() as folder:
    root=Path(folder); audit=[]
    approval={'digest':digest('Reviewed draft A'),'destination':'preview.txt'}
    def publish(text,destination):
        if digest(text)!=approval['digest'] or destination!=approval['destination']:
            return 'needs_review'
        target=root/destination
        if target.exists() and target.read_text()==text: return 'already_published'
        target.write_text(text,encoding='utf-8')
        audit.append({'event':'published','digest':digest(text)})
        return 'published'
    assert publish('Edited B','preview.txt')=='needs_review'
    assert publish('Reviewed draft A','other.txt')=='needs_review'
    assert publish('Reviewed draft A','preview.txt')=='published'
    assert publish('Reviewed draft A','preview.txt')=='already_published'
    (root/'preview.txt').unlink(); audit.append({'event':'withdrawn','digest':approval['digest']})
    assert [row['event'] for row in audit]==['published','withdrawn']
print('exact content and destination approved; duplicate suppressed; withdrawal recorded locally')
```

## Walk through the mechanism and its limits

Approval covers both bytes and destination. An edited date changes the digest and needs review. Repeating the same approved content is recognized instead of producing another publication record. Withdrawal removes only the local mock artifact and retains an audit event. This example has no real external publisher, durable authorization store or concurrent workers; do not infer those capabilities.
