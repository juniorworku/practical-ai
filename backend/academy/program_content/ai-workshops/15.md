## Why this decision matters

Publishing adds an external effect to a drafting workflow. Treat it as a separate permissioned step. Keep preview, approval, publication, and rollback states distinct. An approval should identify the exact content revision and destination; editing the draft invalidates that approval.

Use a local mock publishing directory for this studio. It demonstrates workflow behavior without posting publicly or messaging anyone. Check links, factual claims, accessible headings, and personal data before review. A content workflow should make it easy to retract a mistaken version and identify which readers or destinations were affected.

## Vocabulary used in this session

### Publication approval

Authorization for a particular content revision and destination.

### Content hash

A fingerprint that helps identify whether approved content has changed.

### Withdrawal record

An auditable state showing a published version has been removed or superseded.

No model, network, database service or third-party package is required. SQLite examples create a temporary database and clean it up.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import hashlib, json
def digest(text): return hashlib.sha256(text.encode()).hexdigest()
with TemporaryDirectory() as folder:
    root=Path(folder); audit=[]
    approval={'digest':digest('Reviewed draft A'),'destination':'preview.txt'}
    def publish(text,destination):
        if digest(text)!=approval['digest'] or destination!=approval['destination']:
            return 'needs_review'
        target=root/destination
        if target.exists() and target.read_text()==text: return 'already_published'
        target.write_text(text,encoding='utf-8')
        audit.append({'event':'published','digest':digest(text)})
        return 'published'
    assert publish('Edited B','preview.txt')=='needs_review'
    assert publish('Reviewed draft A','other.txt')=='needs_review'
    assert publish('Reviewed draft A','preview.txt')=='published'
    assert publish('Reviewed draft A','preview.txt')=='already_published'
    (root/'preview.txt').unlink(); audit.append({'event':'withdrawn','digest':approval['digest']})
    assert [row['event'] for row in audit]==['published','withdrawn']
print('exact content and destination approved; duplicate suppressed; withdrawal recorded locally')
```

## Walk through the mechanism and its limits

Approval covers both bytes and destination. An edited date changes the digest and needs review. Repeating the same approved content is recognized instead of producing another publication record. Withdrawal removes only the local mock artifact and retains an audit event. This example has no real external publisher, durable authorization store or concurrent workers; do not infer those capabilities.
