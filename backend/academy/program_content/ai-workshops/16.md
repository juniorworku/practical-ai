# Scope a useful end-to-end application

## The engineering or business decision

A useful app sprint packages a narrow workflow so another person can use it. Pick one of the first five studios and define the smallest complete path from input to saved output and review. Avoid combining every project into one interface. A practical scope includes errors, an empty state, and a known limitation.

Use the academy’s GenAI Accelerator as a source of implementation depth, not a substitute for your project decisions. The planner can help organize a checklist, while the original Accelerator lessons cover infrastructure and evaluation. Your sprint must still supply its own fixtures, user-facing behavior, and acceptance criteria.

## Worked example

Choose the meeting-action register. The release accepts a fictional transcript, produces a draft action table, allows correction, saves the revision, and exports confirmed actions. Live recording, calendar invitations, and automatic task-system writes are excluded.

## Build it yourself

1. Choose one workflow and write a one-page release scope.
2. Define five end-to-end acceptance scenarios including an error and a saved-record reload.
3. Sketch the interface states and API contracts.
4. List dependencies and identify which remain fake or manual in this release.

## Break it deliberately

A tempting integration would take most of the sprint but does not improve the core acceptance scenarios. Defer it and record why.

## Acceptance checks

- The scope has a clear input, output, reviewer, and saved artifact.
- Failure and empty states are included.
- The integration plan identifies real, fake, and manual steps.

## Deliverable

Save **`studio-06/release-scope.md`** in your separate program workspace. Include your inputs, actual outputs, decisions, and unresolved limitations. Budget about **150 minutes** for reading, implementation and review; this is an estimate, not a timed requirement.

## Explain your judgment

Which acceptance check would change your decision if it failed? Explain what your artifact demonstrates and what it cannot establish. Completion in this academy records your own report; the platform does not execute your work or certify it.
