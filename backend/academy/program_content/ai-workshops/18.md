## Why this decision matters

A portfolio should explain what each workflow does, how you tested it, and where it fails. Six superficial demos are less useful than documented prototypes with clear trade-offs. For each studio, include one representative input, output, evaluation summary, and next improvement. Keep all example data synthetic or explicitly permissioned.

Your final app can be the strongest workflow, supported by the other five as focused explorations. Avoid promising production reliability from workshop-scale evidence. A recipient should be able to reproduce the main example and understand which steps are manual, simulated, or integrated with a real provider.

## Vocabulary used in this session

### Reproducible portfolio

Artifacts and instructions let another person repeat representative project behavior.

### Limitation statement

A concrete boundary on what the project has actually tested or supports.

### Evidence-based case study

A narrative that links claims to observed results, failures and decisions.

## Predict before running

Read the assertions and predict the output and rejected cases. Save the **entire** following block as `example.py` in a new scratch folder. Use Python 3.12; every import and synthetic fixture required for this example is included. Run `python3 -I example.py`. Assertions must be enabled; do not use `-O`.
```python
projects=['extraction','meeting','research','triage','content','app']
required={'input','output','evaluation','failure','limitation','setup'}
portfolio={name:{field:'evidence/'+name+'/'+field for field in required} for name in projects}
del portfolio['research']['failure']
gaps={name:sorted(required-set(records)) for name,records in portfolio.items() if required-set(records)}
assert gaps=={'research':['failure']}
print({'coverage_gaps':gaps,'claim':'synthetic prototypes; no client results established'})
```

## Walk through the mechanism and its limits

The index checks presence of named evidence references, not whether those files exist or support the claim. The missing research failure is an honest gap that should narrow the portfolio claim until supplied. Each project needs a concrete input and limitation, and the integrated app needs fresh setup evidence. The final review must open the referenced files and reproduce a representative path.
