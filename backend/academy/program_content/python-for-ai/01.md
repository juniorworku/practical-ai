## Start at the boundary, not at the model
An AI service accepts untrusted data and hands it to expensive dependencies. Treat the request as a contract with a small set of allowed fields. In the example, owner is supplied by trusted application code; query is the only user-controlled value. In the HTTP capstone, credentials determine owner. A type annotation is documentation and static-checker input, so the dataclass still needs a runtime invariant.

## Trace the construction path
1. Python binds the constructor arguments to owner and query.
2. The generated dataclass initializer stores them, then calls __post_init__.
3. The invariant rejects a non-string, empty/whitespace-only query or an excessive character count before an adapter runs.
4. A valid instance is frozen. You can pass it through layers without allowing a downstream function to reassign its query accidentally.
5. The Provider protocol specifies an asynchronous answer method. A fake and a network adapter can satisfy that shape independently.

## Make validation executable
First predict which constructor calls raise. Then run the specimen and compare the observed exception type with the invariant. Add separate cases for a missing value, whitespace, an integer and the exact maximum length. Keep invalid input separate from upstream unavailability: changing the model will not repair a malformed request. Character limits here are an input guard, not token accounting.

## Common mistake: trusting the annotation
A function accepting request: Request can still be called incorrectly at runtime. At an API boundary parse allowed fields explicitly and validate them. Do not deserialize a model-generated owner into a privileged request. Use Protocol for dependency replacement; add an integration test because structural typing does not prove that a remote service behaves correctly.

## Predict before executing

Use a fresh directory, Python 3.12 and a virtual environment. Save the entire block as lesson.py and run `python -I lesson.py` with assertions enabled.
```python
from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True)
class Request:
    owner: str
    query: str
    def __post_init__(self):
        if not isinstance(self.query, str) or not self.query.strip() or len(self.query) > 2000:
            raise ValueError('query must contain 1–2000 characters')

class Provider(Protocol):
    async def answer(self, request: Request) -> str: ...

request = Request('team-a', 'refund window')
assert request.query == 'refund window'
try:
    Request('team-a', '')
except ValueError:
    print('Invalid input rejected before provider work')
else:
    raise AssertionError('empty query accepted')
# frozen=True prevents reassignment; it does not recursively freeze mutable fields.
print('Contract accepted:', request.owner)
```

## Design an immutable request boundary

## Design an immutable request boundary

A production boundary must reject extra fields as well as wrong value types. A dictionary with an owner supplied by a caller must not overwrite authenticated identity. The parser accepts trusted_owner separately, checks an exact key set and copies source IDs to a tuple. This copy removes the alias back to the caller’s mutable list.

1. Read the allowed fields before constructing the object. The dataclass is the validated internal representation, not the JSON parser.
2. Validate the trusted owner, query and each source ID. Python bool is not a useful string or count substitute.
3. Copy nested values to immutable primitives. frozen prevents reassignment; slots prevents arbitrary new attributes, but neither is a recursive authorization mechanism.
4. Mutate the original input list after parsing. The request must retain its original source tuple.
5. Probe extra owner fields, non-dictionaries, boolean queries and non-string IDs. Each must fail before provider work.

This is boundary design rather than a dataclass syntax exercise. The capstone derives ownership from credentials, validates the complete batch and separates InputError from ProviderError so an upstream failure does not masquerade as a caller mistake.

```python
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True, slots=True)
class Request:
    owner: str
    query: str
    sources: tuple[str, ...]

def parse(trusted_owner, body):
    if trusted_owner not in {'team-a','team-b'}: raise ValueError('owner denied')
    if not isinstance(body,dict) or set(body)!={'query','sources'}: raise ValueError('unexpected fields')
    query=body['query'];sources=body['sources']
    if not isinstance(query,str) or not query.strip() or len(query)>2000: raise ValueError('query')
    if not isinstance(sources,list) or len(sources)>4 or any(not isinstance(s,str) or not s for s in sources): raise ValueError('sources')
    return Request(trusted_owner,query,tuple(sources))

original={'query':'refund','sources':['policy-v1']}
request=parse('team-a',original)
original['sources'].append('other')
assert request.sources==('policy-v1',), 'input alias crossed immutable boundary'
for body in [[],{**original,'owner':'team-b'},{'query':True,'sources':[]},{'query':'refund','sources':[3]}]:
    try:parse('team-a',body)
    except ValueError:pass
    else:raise AssertionError('bad body accepted')
try:request.query='changed'
except FrozenInstanceError:pass
else:raise AssertionError('request mutated')
print('Exact schema, trusted identity and immutable nested values verified')
```
