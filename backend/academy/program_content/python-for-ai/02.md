## Separate transport chunks from application records
A socket may deliver half a UTF-8 character, three records at once or the beginning of the next record. Decoding each received byte chunk immediately is unsafe. The generator holds bytes until it sees a newline, decodes one complete JSON record and yields it. The caller decides when to request the next record. This is lazy iteration; list(records(...)) is used only for the tiny test fixture.

## Follow the buffer across yields
1. Append the incoming byte chunk to pending.
2. While a delimiter exists, split exactly one record from the remaining bytes.
3. Enforce the record-size limit, skip blank framing lines and parse JSON.
4. Yield the parsed record. Execution pauses here until the consumer resumes.
5. Check the unfinished remainder after each chunk. At end of stream, reject a non-empty unfinished record instead of fabricating a closing brace.

## Observe a split character
The fixture splits café between its two UTF-8 bytes. Because decoding happens after framing, the record remains intact. Remove the last newline to observe a controlled truncation failure. A newline only establishes transport completeness for a record; an actual provider's done flag is a separate semantic signal. Never cache a token fragment as a final answer.

## Bound every layer
max_line bounds an application record after a chunk arrives; it does not bound the chunk allocated by the HTTP client before this function runs. Configure the transport chunk size and overall response budget too. In an async adapter, await consumption and propagate cancellation when the client disconnects. A stream lowers time to first output but may increase assembly complexity and retry waste; measure both first-output latency and total accepted-answer latency.

```python
import json

def records(chunks, max_line=200):
    pending = b''
    for chunk in chunks:
        pending += chunk
        while b'\n' in pending:
            line, pending = pending.split(b'\n', 1)
            if len(line) > max_line:
                raise ValueError('line budget exceeded')
            if line.strip():
                yield json.loads(line)
        if len(pending) > max_line:
            raise ValueError('unfinished line budget exceeded')
    if pending.strip():
        raise ValueError('truncated stream: missing final newline')

raw = '{"text":"café"}\n{"done":true}\n'.encode()
cut = raw.index(b'\xc3') + 1
output = list(records([raw[:cut], raw[cut:cut+3], raw[cut+3:]]))
assert output == [{'text':'café'}, {'done':True}]
try:
    list(records([b'{"done":']))
except ValueError:
    print('Truncated stream rejected; no false done signal')
else:
    raise AssertionError('truncated stream accepted')
print('UTF-8 and framing preserved:', output)
```

## Prove framing is independent of delivery chunks

## Prove framing is independent of delivery chunks

Testing one convenient network split is weak evidence. The studio enumerates every two-chunk partition of the same UTF-8 byte sequence, including positions inside a multi-byte emoji. It also delivers one byte at a time. These cases simulate segmentation without changing the expected decoded records.

1. Count total bytes before adding a chunk to the pending buffer; reject work beyond the whole-stream allowance.
2. Extract each newline-delimited record and enforce its individual limit.
3. Count nonblank records separately from bytes. Many tiny valid records can exceed work limits despite a small buffer.
4. Validate the unfinished remainder after each chunk and reject truncation at EOF.
5. Hold expected records fixed for every delivery partition. A failed split identifies a framing/decoding defect, not a reason to discard characters.

The parser is a bounded application layer, not a guarantee about the transport’s earlier allocations. The real adapter later reads fixed-size byte chunks and caps the total response before JSON parsing. Its stream=False requests one completed model response; HTTP body streaming is distinct from model token streaming.

```python
import json

def records(chunks, *, max_line=80, max_total=240, max_records=2):
    pending=b'';total=0;count=0
    for chunk in chunks:
        if not isinstance(chunk,bytes):raise ValueError('bytes required')
        total+=len(chunk)
        if total>max_total:raise ValueError('total allowance')
        pending+=chunk
        while b'\n' in pending:
            line,pending=pending.split(b'\n',1)
            if len(line)>max_line:raise ValueError('record allowance')
            if not line.strip():continue
            count+=1
            if count>max_records:raise ValueError('record count')
            yield json.loads(line)
        if len(pending)>max_line:raise ValueError('unfinished allowance')
    if pending.strip():raise ValueError('truncated stream')

raw='{"text":"café 😄"}\n{"done":true}\n'.encode()
expected=[{'text':'café 😄'},{'done':True}]
for split in range(len(raw)+1):
    assert list(records([raw[:split],raw[split:]]))==expected
assert list(records([raw[n:n+1] for n in range(len(raw))]))==expected
for bad in [[raw[:-1]],[b'{}\n'*3],[b'x'*81],[b' '*241],[b'{broken}\n']]:
    try:list(records(bad))
    except ValueError:pass
    else:raise AssertionError('bad stream accepted')
print('Every two-chunk partition and one-byte delivery preserved exact UTF-8 records')
```
