## Learn each concept step by step

## Why a semaphore alone is insufficient
Creating a million tasks and putting a semaphore inside each task still allocates a million task objects. A queue and fixed workers bound both admission and active execution. The example preallocates output slots for a known, deliberately bounded batch; for an unlimited source, emit results to a bounded downstream sink instead.

## Follow producer and consumers
1. The producer enumerates each value and awaits queue.put. A full queue suspends it without blocking the event loop.
2. Two consumer tasks wait for work. Each increments active only while processing an item.
3. Work completes with an await, allowing another consumer to run. This is concurrent I/O-style scheduling, not proof of CPU parallelism.
4. Each consumer stores its output at the original input index, so completion order cannot reorder the returned batch.
5. The producer sends one sentinel per consumer. Every get, including sentinels, has exactly one task_done in finally.
6. TaskGroup exits only after its producer and consumers finish or cancellation cleanup completes.

## Measure the bound
The assertion checks peak active work, not a claimed requests-per-second number. A zero-second sleep yields control; it does not emulate a real provider's latency or rate limit. Change workers and queue capacity independently, then record peak, queue waiting and total latency with a realistic fake delay.

## Error policy is a product decision
Fail-fast cancellation is appropriate when a batch must be all-or-failed. A partial-results API needs explicit per-item statuses and restart semantics; do not catch every exception and replace failed items with success-shaped nulls. If one consumer fails while the producer waits on a full queue, structured concurrency must cancel the producer too.

## Predict before executing

```python
import asyncio

async def map_bounded(values, workers=2, operation=None):
    async def double(value):
        await asyncio.sleep(0)
        return value * 2
    operation = operation or double
    queue = asyncio.Queue(maxsize=2)
    results = [None] * len(values)
    active = peak = 0
    async def produce():
        for item in enumerate(values):
            await queue.put(item)
        for _ in range(workers):
            await queue.put(None)
    async def consume():
        nonlocal active, peak
        while True:
            item = await queue.get()
            try:
                if item is None: return
                index, value = item
                active += 1
                peak = max(peak, active)
                try:
                    results[index] = await operation(value)
                finally: active -= 1
            finally: queue.task_done()
    async with asyncio.TaskGroup() as group:
        group.create_task(produce())
        for _ in range(workers): group.create_task(consume())
    return results, peak

async def main():
    results, peak = await map_bounded(list(range(20)))
    assert results == [n*2 for n in range(20)]
    assert peak <= 2
    print('Ordered outputs and measured peak:', results, peak)
asyncio.run(main())
```

## Force out-of-order completion and measure queue pressure

## Force out-of-order completion and measure queue pressure

A concurrency test should force the scheduling condition it claims to test. Sleeping for guessed durations can fail on a busy laptop. Here an Event prevents input 0 from completing until input 1 has completed. Original indices preserve output order while a completion list records the opposite execution order. The nested producer/consumer functions are closures over queue and output. nonlocal permits rebinding their shared counters; it is not a thread lock or a cross-process synchronization mechanism.

1. Create a Queue with a finite capacity and a fixed number of consumers, not one task per input.
2. Record queue.qsize after each successful put to observe admitted queued work. Active work is a different count.
3. Increment active only around the operation and decrement it in finally.
4. Store the result by original index; verify the completion list is deliberately out of order.
5. In the primary variation inject a consumer failure, catch ExceptionGroup and assert no active operation survives TaskGroup exit.

Queue capacity bounds queued entries; fixed workers bound active calls. The known batch and output array still occupy O(n) memory, so the capstone also caps the input batch at 20. A truly unlimited input source needs a bounded result sink instead of preallocating its entire output.

```python
import asyncio

async def run(values, operation, workers=3, capacity=2):
    queue=asyncio.Queue(maxsize=capacity);output=[None]*len(values)
    active=peak=queued=0
    async def produce():
        nonlocal queued
        for item in enumerate(values):
            await queue.put(item);queued=max(queued,queue.qsize())
        for _ in range(workers):await queue.put(None)
    async def consume():
        nonlocal active,peak
        while True:
            item=await queue.get()
            try:
                if item is None:return
                index,value=item;active+=1;peak=max(peak,active)
                try:output[index]=await operation(value)
                finally:active-=1
            finally:queue.task_done()
    async with asyncio.TaskGroup() as group:
        group.create_task(produce())
        for _ in range(workers):group.create_task(consume())
    return output,peak,queued,active

async def main():
    # Release index 0 only after index 1 completes: ordering is forced, not timed.
    second=asyncio.Event();finished=[]
    async def operation(value):
        if value==0:await second.wait()
        if value==1:second.set()
        finished.append(value);return value*10
    output,peak,queued,active=await run(list(range(20)),operation)
    assert finished.index(1)<finished.index(0)
    assert output==[n*10 for n in range(20)]
    assert peak<=3 and queued<=2 and active==0
    print('Forced completion disorder; ordered results; peak:',peak,'queue:',queued)
asyncio.run(main())
```
