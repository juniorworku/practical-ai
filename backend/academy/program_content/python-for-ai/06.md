## Retry a read, not every exception
The example deliberately raises a custom TransientRead twice. retry_read catches only that class, waits using exponential delays and returns the third response. PermissionError is outside its retry policy and escapes immediately. The application wraps the complete retry loop in one overall deadline from the previous lesson.

## Count attempts as work
1. Validate the retry budget before creating work.
2. Call the dependency and return only a completed result.
3. On an explicitly transient error, check whether any attempts remain.
4. Await the bounded delay so other tasks can proceed.
5. Let the final failure propagate; do not turn exhaustion into an empty successful record.

## Adapt to actual HTTP outcomes
An authorized policy read may retry a 503 or a 429 after a bounded Retry-After value. A 401 requires fixing identity, not increasing attempts. Reject unreasonable server delays against the remaining deadline. In production add jitter with an injected random source so tests can fix the schedule, and capture each attempt's duration and usage.

## AI generation and writes need care
Repeating generation can spend compute twice and produce different text. The final capstone therefore does not silently retry generation. A message-send, payment or calendar write has stronger risks: after a timeout, retain uncertain state and reconcile the original destination using its operation key. A local cache cannot undo a remote action.

## What the test establishes
The fixture proves attempt classification and exhaustion behavior. It does not prove provider-side idempotency or distributed exactly-once delivery. Later release evidence must distinguish a replay-safe read, paid computation and an external effect.

```python
import asyncio

class TransientRead(Exception): pass

async def retry_read(call, attempts=3, pause=0.001):
    if not 1 <= attempts <= 5: raise ValueError('invalid retry budget')
    for index in range(attempts):
        try: return await call()
        except TransientRead:
            if index + 1 == attempts: raise
            await asyncio.sleep(pause * 2**index)

async def main():
    calls = 0
    async def flaky():
        nonlocal calls
        calls += 1
        if calls < 3: raise TransientRead('synthetic 503')
        return 'policy-v1'
    async with asyncio.timeout(1):
        assert await retry_read(flaky) == 'policy-v1'
    assert calls == 3
    async def forbidden(): raise PermissionError('401: do not retry')
    try: await retry_read(forbidden)
    except PermissionError: print('Permission failure surfaced immediately')
    else: raise AssertionError('permission failure became success')
    print('Bounded safe-read attempts:', calls)
asyncio.run(main())
```

## Make retry policy deterministic with an injected clock

## Make retry policy deterministic with an injected clock

The original example teaches bounded attempts. The advanced studio separates policy time from real I/O time so backoff decisions can be tested without waiting or relying on a lucky scheduler.

1. Compute one end time from the total policy budget.
2. Catch only TransientRead. Permission and malformed-input failures escape immediately.
3. Choose the greater of exponential backoff and the adapter’s validated Retry-After delay.
4. Reject a sleep that consumes the remaining allowance, rather than exceeding the budget and hoping the next call succeeds.
5. Inject clock and sleep. The fake sleep advances policy time and records exact delays; production still needs an async timeout around real network work.

The TransientRead exception carries already-parsed retry metadata in this local fixture. A real adapter must validate and cap upstream header values first. Optional jitter may reduce synchronized retries in production but needs its own seeded/bounded test policy. This read-only capstone intentionally does not auto-retry provider failures; callers see honest errors without hidden amplification.

## Complete advanced studio

Save this entire block as studio.py and run `python -I studio.py` with Python 3.12. It is a standalone standard-library exercise; it does not import another lesson. Predict the assertion outcomes before running.

```python
import asyncio

class TransientRead(Exception):
    def __init__(self,retry_after=0):self.retry_after=retry_after

async def safe_read(call, clock, sleep, *, budget=1.0, attempts=3):
    end=clock()+budget
    for number in range(attempts):
        if clock()>=end:raise TimeoutError('overall budget')
        try:return await call()
        except TransientRead as error:
            if number+1==attempts:raise
            delay=max(.1*2**number,error.retry_after)
            if delay>=end-clock():raise TimeoutError('backoff would consume budget')
            await sleep(delay)

async def main():
    now=[0.0];waits=[];calls=0
    def clock():return now[0]
    async def sleep(delay):waits.append(delay);now[0]+=delay
    async def flaky():
        nonlocal calls
        calls+=1
        if calls<3:raise TransientRead(.25)
        return 'policy-v1'
    assert await safe_read(flaky,clock,sleep)=='policy-v1'
    assert waits==[.25,.25] and calls==3
    async def unavailable():raise TransientRead(2)
    try:await safe_read(unavailable,clock,sleep)
    except TimeoutError:pass
    else:raise AssertionError('Retry-After exceeded budget')
    assert waits==[.25,.25], 'do not sleep when there is no remaining allowance'
    print('Injected clock proves attempt and backoff policy without timing guesses')
asyncio.run(main())
# The real call also needs an async timeout: a fake policy clock cannot interrupt I/O.
```
